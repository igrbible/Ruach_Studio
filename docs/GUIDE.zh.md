# Ruach Studio · 指南

从文字到歌曲，在你自己的机器上：每个房间、每样东西做什么，以及我们测得的数字。

## 从这里开始 <!-- #start -->

### 这是什么 <!-- #what-this-is -->

Ruach Studio 用开放的歌曲模型 **YuE2** 把一行风格描述和歌词变成一首完整的歌，在你自己的 GPU 上运行。什么都不会离开这台机器。模型周围是一整座工作室：带聊天模型的写作室、后期制作（分轨、重制母带、超分、歌词检查）、所有录音的收藏，以及一个用你自己的歌训练 LoRA 适配器的房间。

![创作室：左边是表单，中间是录音，右边是所有录音](guide/studio-create.png "创作室：表单、你正在听的录音，以及你所有的录音")

YuE2 有 **两半**，你在工作室里设置的大多数东西都针对其中之一：

| 一半 | 做什么 | 你在那里控制什么 |
|---|---|---|
| **音乐**（AR，语言模型） | 写歌：先写乐谱（ABC 记谱），再写音乐令牌，每秒 25 个 | 规划模式、乐谱、音乐种子、LoRA 的音乐强度 |
| **声音**（NAR + VAE） | 把令牌渲染成声音 | 声音种子、VAE、LoRA 的声音强度、步数和求解器 |

### 六个房间 <!-- #the-six-rooms -->

| 房间 | 用途 |
|---|---|
| **创作室** | 歌曲表单和你正在听的录音 |
| **写作室** | 你的歌作为带版本的文档；聊天模型和你一起起草、修改 |
| **精修室** | 渲染之后：频谱、伪影、去嗡声、歌词检查、分轨、重制母带、超分 |
| **画室** | 用你自己的提示为歌曲作画：一个种子出方形、宽幅和竖幅；方形的一张可作为录音的封面（早期预览） |
| **资料馆** | 所有录音：工作区、搜索、喜欢、备注、批量操作、回收站 |
| **LoRA 训练室** | 用你自己的歌训练 LoRA 适配器：数据集、运行、遥测和各个轮次 |

### 栏 <!-- #the-bar -->

![栏：各个房间、工作区，以及你一直会用到的几个按钮](guide/bar.png)

房间按工作顺序排在栏的开头：创作室、写作室、精修室、画室（早期预览：为你的歌作画）和资料馆；标志在中间，训练室紧随其后；右边是工作区、引擎的指示灯（绿：就绪；琥珀：工作中；红：有东西失败了）和几个按钮。指针放在指示灯上（或点击）会打开 **正在运行和正在等待的**：歌曲、重新生成，以及实验室在显卡上的工作（封面图、分轨、超分、Whisper）。等待中的项目按两次它的 ✕ 即可移出队列（第一次会询问）；已经在运行的在显示它的地方停止：歌曲在它的运行里，训练在训练室里。

- **工作区**：手头的工作区。录音列表只显示它，每个新录音都落在其中。*全部工作区* 显示全部。栏较窄时（那里没有标志），*工作区* 这个词也会隐去，框保留。
- **EN**（语言的两个字母）：把页面切换到另一种语言，随设置保存：English、Русский、Українська、Беларуская、Ελληνικά、Español、Italiano、Français、Português、Deutsch、日本語、中文，每种都用它自己的文字命名。数字和日期跟随语言，本指南也以该语言打开。
- **☀ / ☾**：白天、夜晚，或跟随系统。
- 在“作曲”的标题栏里：把提示（“生成”会发送的全部内容）以 JSON 或 YAML **保存**，并再次 **打开**；**清空** 文字（标题、风格、歌词、乐谱、种子）而保留其余，或开始一首 **新歌**（模式、采样、滑块和 LoRA 也回到默认；*声音与输出* 保留）。**打开** 会说明表单未能从文件中接收的内容，以及文件里取而代之的内容。
- **导出到 DAW**（在 ☰ 中，以及在精修室：手头录音旁边和它的分轨里）：离开工作室的出口。要么原样导出混好的音轨（WAV、FLAC、MP3），要么把整段录音导入你自己的 DAW，其余的在工作室之外进行。页面会在工作室的机器上找到 REAPER、Waveform 和 Bitwig，或由你指定自己的。任何录音都可以从它的菜单（右键）导出：*导出到 DAW → REAPER 项目* 或 *DAWproject*（Waveform、Bitwig、Studio One、Cubase），你自己的 DAW 排在最前；本指南的 DAW 标签页说明里面有什么。
- **卸载模型**：立即把所有空闲模型移出 GPU 内存；有模型加载时显示为红色。
- **☰**：其余的。显卡及其内存、模型副本、声音解码器（VAE）、**导出到 DAW**、主题、引擎房间和本指南。那里的 **文字大小** 把整页文字设为 −2 到 +4 pt（布局不变），分离出的框在上方有自己的 −、+ 和 ⟲（−4 到 +6 pt）；每个屏幕各自保存。

### 你的第一首歌，六步完成 <!-- #your-first-song-in-six-steps -->

1. 给它起个 **标题**，心里有调的话选好 **调**（否则保持 *按原样*）。
2. 写下 **风格**：语言、流派、嗓音、乐器、速度。一两行平实的话就够了。旁边的 ♪ 列出 200 种乐器，以及 YuE2 实际演奏出来的样子（见 *创作室*）。
3. 粘贴 **歌词**，段落标签各占一行：`[Verse]`、`[Chorus]`、`[Bridge]`、`[Outro]`。
4. 规划模式保持 **完整规划**：YuE2 先写旋律与和弦，再写歌。
5. 按 **生成歌曲**。运行会显示各个阶段：乐谱、音乐令牌、声音、解码。
6. 录音在中间打开，带着它的播放器、乐谱，以及再次制作它所需的一切。

> 在 RTX 3090 上实测：直接模式下一首 6:12 的歌用了 126 秒，完整规划下一首 7:25 的歌用了 198 秒（先写乐谱）。歌越短越快。

### 播放器、录音和服务器日志 <!-- #the-player-the-takes-and-the-server-log -->

- 底部的 **播放器**：横贯的波形，一片柔和的云，已听过的部分显示为强调色（点击即可跳到那里）；下方是录音（有封面时显示封面、标题、风格的开头几个词、👍 👎 ★），然后是 **随机播放**、上一首、播放、下一首和 **重复**（关闭 · 整个列表再来一遍 · 这段录音再来一遍，标为 1），然后是时间（点击总时长会切换为剩余时间）、*点击即播放*（在列表中点击会立即播放该录音）、*连续播放*（一段录音结束后列表中的下一段开始）、*播放新录音*（这里做好的歌完成时会播放，除非正在播放别的）、🔔 *运行结束时的提示音*（完成时两个上行音，一串运行只响一次，失败时两个下行音；自动开始播放的新歌上不叠加）、**速度**（0.50× 到 2.00×，音高不变）、音量和一个表示状态的点（播放录音时它会跳动）。此刻用不到的东西会保持淡色，直到指针移过来；每个图标在指针停留时都会说明它的作用。波形上的指针显示点击会跳到的时间。键盘和耳机的媒体键可以控制播放器，桌面的媒体面板会显示这段录音。⏪ 和 ⏩ 跳到从 0:00 起每 15 秒一个的上一个或下一个刻度，← 和 → 跳到每 5 秒一个的刻度（Shift：30 秒）。播放器右端的状态标签（播放录音时为绿色，制作中为强调色）会打开这段录音或这次运行；当“作曲”分离悬浮在房间上方时，它会把框切换为该录音的。在波形、图片或标题上右键，会像在列表中一样打开录音的菜单。波形显示录音的段落：歌词自己的标签，每个都在 Whisper 听出其第一行的位置（每段录音一次，约半分钟；在有两块或更多显卡的机器上自动进行，否则用录音菜单 → *凭耳朵找出段落*）；从未被听过的录音显示其乐谱的标记。每个开头一条细线，名称在底部；在线附近点击会跳到该段落的开头；波形上的指针会显示一张卡片，含段落、时间和按原文的歌词，正在唱的那一行高亮；带 ? 的段落表示没有听清。指针在波形上停留片刻，整段录音的频谱图会出现在播放器上方（🔔 旁边的频谱开关可以关闭它）：与波形同宽、时间对齐，约为窗口高度的三分之一，段落卡片在它上方；其中有段落、以洋红线表示的频谱质心（声音的重心所在：它的明亮度）、底部条带中的 RMS 以及录音自身平均值的虚线、播放头；指针下方是它的时间，那一刻的频谱画在线旁，带有最响的频率和音名，图中更高处是那里的频率、音名和电平。标题栏中选 *对数* 或 *线性*；点击像在波形上一样跳过去；指针移开或按 Esc 会收起它。录音只由实验室测量一次，与它的频谱相同。
- **两行或一行**：在需要聆听和比较歌曲的地方（创作室、精修室、资料馆），播放器把波形放在控件上方；在写作室、画室、训练室和引擎中，以及在创作室中有框分离或歌词置于最上时，它只占一行。重新加载（F5）后，它会带着原来的录音和位置回来。在画室中，录音栏开始时是收起的，服务器日志位于左侧。
- **显卡，实时**：在 引擎 → GPU 中，每块显卡下方有自己的一行，两分钟内每秒一格显示负载和内存，以及温度和功耗；服务器日志展开时，旁边会显示有角色的显卡，每块以其角色为标题，工作室的显卡带框。
- **到工作室的连接** 显示在服务器日志旁边（*Forge · 85 ms*，同一台机器上为 *此处*）。工作室在远处时，喜欢、收藏或置顶会立即显示，工作室只是确认。
- 右侧的 **录音**：用词语、`*` 和 `?` 搜索；*收藏*；用 » 收起该栏；⋯ 是列表自己的操作。
- **服务器日志** 在每个房间都位于播放器正上方：收起时显示引擎最后说的话（有东西失败时为红色）；展开时显示十行、*跟随*、*复制*，以及到引擎中完整日志的入口。当有框分离悬浮在房间上方时，它位于左侧，避开框的按钮。其内侧边缘的箭头会把它移到页面另一侧，每个房间记住自己的那一侧（画室是左侧）。拖动其外侧边缘可加宽，最多 1200 px（会保存；双击恢复原宽度）；旁边有显卡时宽 920 px，显卡栏宽 390。这个框有两个视图，**服务器** 和 **画室**（画室自己的日志：请求了什么、实验室如何回应、每次运行直到结束的过程），每个房间打开自己的那个；**⧉** 在单独窗口中打开日志，在 Chrome 中置于所有窗口之上，或拖到另一台显示器上。

## 创作室 <!-- #creator -->

### 作曲：歌曲表单 <!-- #compose-the-song-form -->

![标题、调、种子和风格](guide/compose-top.png)

- **从一个想法开始**：关于这首歌的一行话；写作室的聊天模型会起草标题、风格和歌词（*写简报*）。
- **标题**、**调**：调会写入乐谱（`K:`）。表单里有乐谱时，新的调会把它移到那里；没有乐谱时，这个选择会等着，移调随后到来的乐谱。
- **音乐种子** 和 **声音种子**：两半各自的骰子。留空即随机；填一个数字可以重现一段录音。保留音乐种子、改变声音种子，可以听到同一首歌的另一种渲染。它们排在 *采样与去噪* 的最前面。每个旁边是它的 **模式**：*随机（−1）* 每次运行一个新种子（字段留空），*随机，固定* 放入一个随机种子并保留，*固定* 用写下的那个，*下一个* 和 *上一个* 在每次“生成”之后越过已用过的种子移动它（音乐上是版本，声音上是变奏）。画室的种子也有相同的模式。
- **风格**：语言、流派、嗓音、乐器、速度。*保存风格…* 以一个名字保存它。标题栏中的 **♂** 和 **♀** 会把 *male vocals* 或 *female vocals* 放进去（替换另一性别的词，否则放在 BPM 之前）；点亮的那个会去掉它的标签。 旁边的**自由速度**用去掉速度标记（Q:）的乐谱生成音乐：人声和节拍自己呼吸，歌词不再被小节束缚（rubato、非线性）；当风格要求 rubato 或 non-linear 且没写 BPM 时自动开启，开启时风格里若有 BPM 会在框下提示。单独生成的乐谱（*创建 ABC 乐谱*）也不带速度。

### 乐器速查表 ♪ <!-- #the-instruments-cheat-sheet -->

风格旁边的 ♪ 会打开一张表，列出工作室试过的 200 种乐器：类别、出处、听起来怎样（英文和俄文），以及召唤它们的词。▶ A 和 ▶ B 播放每种乐器的两个 60 秒样例。每一行的结论来自人耳：听得到、存疑，或 **NOT IDENTIFIED IN YUE2**（YuE2 不认识它；需要更讲究的提示）。点击会复制名称并询问放到哪里：在风格末尾单独一行，或替换它；风格中已有的名称会在表中标出，表中的文字可以选中并复制。

**乐器何时进入由 YuE2 决定。** 风格这一行是请求，不是命令：无论你多么用力地要求，模型都会在它的训练认为歌曲需要的地方引入乐器，而种子起很大作用。同一个提示得到过一段有这件乐器的录音和一段没有的。评判一件乐器之前，先听几个种子。

**听得到，但不如真乐器真实。** 许多乐器确实会演奏，但不如真东西清晰、逼真：这就是 YuE2 对它们的了解。结论说明 YuE2 是否演奏某件乐器，而不是它听起来有多真。让它变得真实是 **乐器 LoRA** 的工作：几十段这件乐器的干净录音，在 LoRA 训练室里训练。

### 歌词与文本配置 <!-- #lyrics-and-text-profiles -->

- 段落标签各占一行；YuE2 认识 `[Intro]`、`[Verse]`、`[Pre-Chorus]`、`[Chorus]`、`[Bridge]`、`[Interlude]`、`[Outro]`。
- **文本配置**：粘贴一整段文本，选一个配置，*应用*：它的规则（清理、注音）和形式（在空行处加 `[Intro]`、`[Verse]`，长段落后加 `[Interlude]`）让文本可以朗读。*撤销* 会把文本恢复。配置在写作室中制作。

### 歌词的节拍与注音写法 <!-- #the-lyrics-meter-and-the-phonetic-hand -->

- 歌词旁边的 **节拍**：每一行的音节以条形对照其所属组的标尺 —— 主歌和桥段一组，预副歌自成一组，副歌自成一组，其他段落各自一组。演唱段落中的停顿、Break、静默、间奏、前奏或器乐提示不会开启新组：它的名称淡淡地显示在旁边，段落的标尺继续。标签从不计数：只有标签的一行（`[Break] [Silence]`）计为零，行内的标签被略过。标尺位于该组的通常长度；相差一个音节以内条为绿色，相差两三个为琥珀色，更多为红色。圆括号里的内容在条后以斜线绘出：YuE2 可能会唱出来。输入框下方：歌词的字符数、音节数和行数、段落标签、括号以及注音写法；浏览器按歌词语言做的拼写检查（在那里关闭）；手动拉高的输入框会保持高度，直到点 *自动高度*。
- **行号和标记**：歌词框像代码编辑器一样给行编号（换行的一行只编一次，在它的第一行；框下的 *行号* 可以关闭）。**Alt+K** 标记或取消标记光标所在行，**Alt+J** 跳到下一个标记，**Alt+Shift+J** 跳到上一个，**Alt+Shift+K** 全部清除；被标记行的行号为琥珀色，在上方书写时标记会跟着它们的行走。每个 [标签] 下都有一层薄薄的琥珀色。写作室的歌词也一样。与 mcedit 相同：**Alt+O** 也能清除标记，**Alt+L** 按行号跳转，**Ctrl+Y** 删除该行，**Alt+↑** 和 **Alt+↓** 连同标记移动该行（或所选的行）。框下的 *按键* 列出全部，写作室的“歌词”标签在悬停时也会显示。歌词旁的 **⤢** 让输入框置于最上，宽为屏幕的 60 %，放大四成，带有以上全部功能，以及调整文字大小的 −、+ 和 ⟲（保存在此浏览器中）；Esc 放回原处。**⤢** 旁边的两个按钮以纯文本处理歌词：第一个把它保存为以标题命名的 `.txt`，第二个用一个 `.txt`（UTF-8）替换歌词（框中有文字时先询问，在框中按 **Ctrl+Z** 可恢复；标题为空时使用文件名）。
- **括号检查**：在本行未闭合的“[”、没有对应开括号的“]”、标签内的“[”以及空标签会让该行行号变红，框下的 *未闭合或错位的标签* 可以逐个跳转；未闭合或没有开括号就闭合的圆括号为琥珀色（回声可能延续）。正在输入中的“[”会被放过，直到光标离开那一行。标签损坏时 **“生成”会先询问**：未闭合的“[”之后的内容可能在歌中丢失，结尾也可能出错；可选 *跳到该行* 或 *按原样生成*。
- **错位的重音符**：不在元音上的标记 —— 在行首、在空格或符号之后、在辅音上、同一字母上的第二个，或用带间距的 ´ 代替 —— 会在框下显示一个红色按钮（*不在元音上的重音符*），并在该行计数前加标记；按钮会依次选中每一个。有两个标记的词会得到一个琥珀色标记：有意的，还是笔误？计数时重音符不算音节；俄语单词中的 ע 和拉丁元音算。一个音节就是一个元音、一个音符，按各语言的规则计数：俄语、乌克兰语和白俄罗斯语中一个元音字母为一个（由于节拍衡量一行所需的时间，没有元音的词 —— с、в、к、з、й、ў —— 以及词内在塞擦音前闭合的塞音 —— глу-п-цо́в —— 各占一拍，颜色较浅：“Я же вижу глупцо́в с приду́рческим планом”是 12 个音节加 2 个这样的拍，共 14）；希腊语中 αι、ει、οι、ου、αυ、ευ 算一个（分音符或重音会把它们分开：τσά-ι）；西班牙语和意大利语中弱元音 i 或 u 与相邻元音合并（cie-lo、cuo-re），两个强元音算两个（po-e-ta）；英语中词尾不发音的 e 不算（make，但 ta-ble）；希伯来语数它的元音符号；中文、日文和韩文每个字一个。拉丁字母的词按英语、西班牙语或意大利语计数：依据风格中表示语言的词，否则依据歌词本身的小词。
- 在歌词或风格（以及写作室的输入框）中按 **Ctrl+F** 只在该框中查找：Enter 和 Shift+Enter 在匹配间移动，在查找栏中按 Esc 会把光标放回并选中匹配；从框本身（在别处点击过）则关闭查找栏，光标留在原处，期间在那里输入的文字不会移动视图。重音符不参与查找，ё 视为 е，о 和 а 也能找到 ע 以及拉丁字母 o 和 a。**F4** 或 **Ctrl+H** 打开第二行用于替换：**Enter** 用新文字替换当前匹配并转到下一个，**Ctrl+Enter**（或 *全部*）一次替换所有匹配，在框中按一次 **Ctrl+Z** 即可撤销；**Aa**（**Alt+C**）只按输入的大小写查找。
- **“[”下的标签**：在歌词（创作室或写作室）的行首输入“[”，会像代码编辑器提供词语那样打开段落标签，按一首歌经过它们的顺序，从 Intro 到 End。之后输入的字母会缩小列表（俄语或乌克兰语键盘布局也可以），数字会给标签编号（`v2` 即 `[Verse 2]`），给主歌编了号的歌词会得到下一个编号。↑ ↓ 选择，Enter 或 Tab 把标签放在单独一行（Ctrl+Z 撤回），Esc 或 `]` 关闭列表。歌词中已有的 Intro、Outro 和 End 连同它们的行淡淡地留在原处：↑ ↓ 可以选到并读到它们是什么，但不会放第二次。Ctrl+Space 打开列表，在行首则直接输入“[”。列表分两栏：标签，以及旁边当前标签的说明（用我们的话，参照 Genius 的歌曲段落指南）和 110 个官方示例写它的次数；列表缩小时输入框大小不变。没有任何示例写过的段落标为 TEST。一行中的 **第二个和第三个标签**：紧接在行的标签之后输入“[”会自动加空格，并提供不是段落的标签（谁来唱，按示例的写法；Female Vocals、Break 和 Silence 标为 TEST）；Enter 把它放在同一行，其中的“…”被选中以便填写你的词；在那里 Ctrl+Space 也会输入“ [”。
- **注音写法**（Viktor 的，源自 SUNO；YuE2 也遵循）：
  - 元音之后的 **重音符**（组合用锐音符，U+0301）：`обе́щано`、`сули́т`。在约 90 % 的句子中有效；其余看种子的运气。
  - **大写的重读元音** 会违背词典，把重音推到押韵需要的位置：`базилиО́`。只有大写而没有符号（`дрОв`），很少能移动重音。
  - **俄语单词中的 ע（ayin）** 唱成柔和的 о/а，就像口语中非重读的 о：`кעмо́рка`、`пעле́но`、`Ка́рлע`。它也能给越来越快的说唱踩刹车。
  - **俄语单词中的拉丁字母 o** 在模型会说 а 的地方唱成硬而开的 o：`Кo дну`。
  - **拉长的元音**（`о-о-о`、`БУ… РА… ТИ… НО`）撑住一个音；在音乐留有空间的地方，而不是每一句。
  - 各部分之间的 **[Interlude]** 会在说唱中制造停顿，并让不断加快的说词慢下来（并非总是）。
  - **圆括号** 不是指令：其中一两个歌词语言的词，大多会被唱成合唱回声；括号里的指示（`(Music slowly fades)`）大多被跳过，或被唱出来。指令写在方括号里。
  - **带元音符号的希伯来语单词**（`רוּחַ`）模型说得比音译更好。
  - **方括号是给 YuE2 的指令**：段落、嗓音、这一句是唱还是说。这里可玩的东西很多。
- **嗓音**（不是段落：歌词行仍属于前面的段落）。Viktor 的写法：唱的行用 `[Vocal: Female - …]` 或 `[Vocal: Male - …]`，说的行用 `[Spoken: Female - …]` 或 `[Spoken: Male - …]`；先写谁，破折号后写怎么（`[Spoken: Female - Soft Whisper, Intimate, Sacred]`）。说话标签可以直接放在行首：`[Spoken: Female - Soft Whisper] Ты слышишь?`。在一首使用男声适配器和女声旁白的长叙事曲中（2026 年 10 月 13 日），YuE2 约 95 % 的时候听从了这类标签，比 SUNO 更稳定。嗓音标签里的 **Solo** 不会被听出来（示例只把它用于乐器：`[Guitar Solo]`）：请直接写出嗓音。「[」会在段落之后列出它们，并标为 *不是段落*。
- **一个音节会改变整首歌。** YuE2 在写音乐之前把歌词当成一条链来读：改一个音节、一对 «»、一个标签，同一个种子从那里到结尾都会走另一条路。种子是骰子，不是歌。要改一句而保留其余部分，请替换它所在的段落（右键点击播放器的波形）；要判断新的歌词，请用几个种子去听。
- **时长**：YuE2 能撑住 8 到 9 分钟的歌，比 SUNO v6 的 6:15 更长。*最大时长* 可达 15 分钟用于叙述，但超过 9 分钟就看种子的运气了。

### VAE、滑块和 LoRA <!-- #vae-sliders-and-loras -->

- **VAE** 把写好的歌变成声音：**标准**（最好的声音）、**旧版**（基准测试用的那个）、**混合**（两者的混合，一个附加组件）。完成的录音以后可以在自己的页面上再加一个解码。它在 **☰** 菜单中模型下方选择，作用于之后的歌；一段录音可以在其卡片上用另一个 VAE 在几秒内重新解码（从 rc2 起每段录音都保存潜在表示；之前做的会重新渲染声音）。
- **滑块**：在写音乐时施加的流派和嗓音塑形；0 为关闭，1 为最大。
- **LoRA**：用于音乐部分、声音部分或两者的适配器，各有自己的强度。

**滑块的曲线。** 滑块从第一秒到最后一秒都以同样的强度推动：平直。强度旁的小图会打开它的曲线：**拱形** 让它在歌曲中段升到满强度，在两端减弱；**绘制** 用手塑形：把一个点往上拖是增强，往下是减弱，沿歌曲拖动是移动它；双击添加一个点，双击某个点则删除它。你设定的强度是曲线的顶点。曲线在写音乐时从第一帧一直覆盖到歌曲长度的末尾，并写入录音的请求中，所以重新制作的录音会走同一条曲线。

![LoRA：每个强度都在从绿到红的路上，还有音乐部分的合计](guide/loras.png)

每个强度都在一条 **路** 上：绿色安全，黄色是上限，红色已越过。上限都是测出来的：

- 乐谱适配器（规划 ABC 的那种）到 1.0 为绿色；其他音乐部分到 0.5 为绿色，最多 0.75；在本工作室训练的适配器在音乐部分更严格（0.5 绿色，0.6 上限）；
- 声音部分到 1.0 为绿色，上限 1.5；
- **音乐合计**：叠加的适配器会相加。每个都可以在自己的绿色范围内，而总和仍可能弄坏乐谱。在真实录音上测得：合计到 **2.25** 完好，从 **2.5** 开始损坏。适配器下方的条在同一条路上显示合计。

**双击** 数字可以精确输入强度。区块下方的提示说明要点：风格中缺少的触发词、在另一种规划模式下训练的适配器、超过上限的强度。指针停在滑块上或拖动它时，精确的强度会以所在路段的颜色显示在指针上方。Instrumental 适配器止于它起始的 1.0：超过后，它的乐谱会跑偏。

> **带有要唱的歌词的器乐乐谱适配器。** 这种适配器规划的乐谱 *没有人声旋律线*。在 1.00 时，它给出的录音在 127 个人声小节里只有一个音：歌手在两个循环的小节上说话。有歌词时把它调低，0.3 到 0.5。发生这种情况时，LoRA 名称旁的 ⚠ 会提示。

### 配置与规划模式 <!-- #profiles-and-planning-modes -->

- **配置** 一次设定模式、长度、采样、引导、步数、VAE、滑块、LoRA 和输出；文本和种子不变。*保存配置…* 以一个名字保存当前的参数。
- **规划模式**：
  - **完整规划**，默认：先写旋律与和弦（可编辑的乐谱），再写歌。最适合新歌。
  - **仅旋律**：旋律规划，伴奏自由。推荐用于翻唱。
  - **直接**：直接从歌词和风格生成，没有乐谱。不带乐谱训练的适配器属于这里。
  - **纯音乐**：没有人声，YuE2 官方配方。它位于规划模式标题栏的右侧。
- **完整还是直接。** Viktor 做了一周歌之后的话：直接模式像 SUNO 那样靠运气（照他的统计，一百段里大约两段好的）；完整规划是适合所有人的路，哪怕一个 ABC 音符都不会读：标签被遵守，声音稳定，吐字清楚，速度可以预见。在他的说唱上测量，每种各 14 段录音，由 Whisper 听写：所有录音中最好的一段是用他的保守配方做的完整规划（听出 84 % 的词，最后四分之一为 76 %）。完整规划出问题时，问题出在结尾：录音和乐谱一样长，而规划中的段落可能比文本少（于是最后几段主歌被略去，或前面某段被再唱一次）；最后的歌词之后，乐谱剩下的小节还会继续演奏，这就是歌曲应有的淡出之后多出的 10–15 秒，不是引导造成的。听一听完整规划录音的结尾：*结束于…* 剪掉尾巴，*从…重新生成* 重写丢失的结尾。

### 翻唱、混音和你自己的乐谱 <!-- #covers-remixes-and-your-own-score -->

- **翻唱或混音**：取一段录音的曲调（*扒谱*：只取旋律，不取歌词或歌手），或你某段录音的旋律，给它一个新风格。
- **提供你自己的乐谱**：一份 ABC 乐谱，在完整规划和仅旋律模式下遵循。可以移调（就近、向上或向下），按音阶级数移动一个声部，导入 MIDI 文件（每个声部一条旋律线），为 DAW 导出 MIDI 或标记，加载示例，把它变成纯音乐。这里有乐谱时，**生成** 会先询问：用这份乐谱，还是新的一份（清空字段，由歌曲模型写一份）。乐谱会记住写它时所用的适配器和音乐强度（一个规划、录音自己的乐谱）；当前启用的不同时，下方会有一行提示，询问时也会说明：在其他强度下音乐可能偏离乐谱，Industrial Rock 和纯音乐最明显。在完整规划中，只要有乐谱，乐谱区就保持展开。
- **在乐谱上朗诵歌词**（乐谱可以读取后，下方出现 *把歌词放到这份乐谱上…*）：工作室宣传片里的那位旁白，换成你的词。每一行放在乐谱的小节上，每个音节一个八分音符（像说唱那样，用八分音符会有行放不下的地方用十六分音符），落在所在小节和弦的一个音上，逗号和句号后换气，行末音节用四分音符并降低；每个段落在一小节休止之后（勾选时则在一段元音吟唱之后）以两小节的乐句开始。乐器、和弦、调和速度不变；乐谱的段落跟随你的标签，前后加上前奏和尾奏。适用于说白、朗读和伴奏上的说唱：先做伴奏，*从声音写出来*，再用这个；它会先询问，在各输入框按 Ctrl+Z 可恢复原来的文本。

### 采样与去噪 <!-- #sampling-and-denoising -->

![采样：乐谱规划器和音乐令牌，令牌上下限已锁定](guide/sampling.png)

默认值已经调好。三行 **形态**（作曲、演绎、风格）以五个档位一起调整参数；参数本身在下方。

- **乐谱规划器** 和 **音乐 token**：温度、top-p、top-k、重复惩罚、惩罚窗口。
- **最少 token** 和 **最多 token** 被 **锁定**，以防误改：点名称旁的 🔒 可以修改，再点一次锁上。下限是保险丝：乐谱不能在 200 个令牌之前结束，音乐不能在 750 个（30 秒；要求的时长更短时降到该时长）之前结束。音乐的上限显示为 **最大时长**，以时间计（每秒 25 个令牌），没有锁：它就是歌曲时长的上限，只在这里设置（声音与输出中没有时长字段）。
- 每个参数都被限制在合理范围内；超出的值会被拉回，页面会提示。
- **引导（CFG）**：音乐的引导，即音乐阶段中风格的牵引；每种模式默认为 1.6。
- **歌词引导**：歌词自己的引导，与风格分开：在引导一直拥有的两条分支旁，再加一条不含歌词的提示词分支；默认 2.2。维克多在一首民歌上的耳朵：引导 4.0 配歌词 2.2 最明亮，3.0 配 2.2 同样明亮，3.0 配 1.6 有自己的深度，歌词 2.6 会把沙锤推到前面；在 1.6 时歌词如天鹅绒般融化。两者相等时，一半歌词会滑向幻听，С（s）丢失，元音重音也会歪：让两者相差 0.4 到 1.0。每个字段旁的灯会提示：在他的范围内（音乐 1.0–4.0，歌词 1.0–2.6，相差 0.4 或更多）为绿色，稍超出为琥珀色，远超出为红色；不做任何钳制。留空时歌词跟随引导，与以前一样。
- 区块下部的 **声音与输出**：声音部分的 **去噪步数** 和 **求解器**，**格式**（WAV 24 位、16 位、32 位浮点，或带码率的 MP3）和 **削峰**；*重置输出* 把它们恢复。

**俄语的保守配方**（Viktor 凭耳朵定的）：作曲 *低*、演绎 *低*、风格影响 *高*：乐谱规划器温度 0.85、top-p 0.92、top-k 40，音乐令牌 0.85、0.93、80，重复惩罚 1.005 和 1.3，窗口 100，引导 1.6，歌词引导 2.2；Midpoint 32 步去噪。不加速，说唱用适中的速度。这就是内置配置 *Musical Heresy of Creator's Ear*，由维克多调整：在配置中覆盖保存会把他的数值留在 Forge 上，删除则恢复这些数值。

### 创建 ABC 乐谱，然后生成 <!-- #create-abc-score-and-generate -->

- **创建 ABC 乐谱** 写出乐谱后停下：阅读、编辑，然后 *生成* 会准确地渲染这份乐谱。字段里已有的乐谱会在询问后被覆盖。
- “生成”旁边的 **样例** 和 **变体**：样例是要做几个样例，每个都重新写音乐，各用一个音乐种子（种子、种子 + 1…）；引擎一次写批量允许的数量，其余在后续轮次中完成。变体是每个样例的同一段音乐要渲染几次声音，各用一个声音种子，每个样例都相同：每次大约花一次声音的时间，几乎不占内存。产出 样例 × 变体 段录音：2 × 4 = 8。
- **生成歌曲** 运行全部。运行过程中会依次显示各个阶段。

### 乐谱里的巴别塔 <!-- #babel-in-the-score -->

![引擎停止了一次乐谱不成乐谱的运行](guide/babel.png)

当音乐部分把乱码当作乐谱写出来时（被推过上限的适配器会这样：没有调号、没有拍号、一连串的冒号），**引擎会在任何音乐基于它生成之前停止这次运行**，用几秒而不是几分钟。窗口会说明原因、哪些适配器压在音乐部分上以及超出上限多少，显示写出的内容，并能一键把音乐强度调回绿色范围。

### 录音 <!-- #the-take -->

![一段录音：下载、重做、后期、文件](guide/take-head.png)

- **标题栏**：第一行是 ▶ 和录音的按钮（👍 👎 ☆、资料馆、重命名、删除），行尾是 ⇆ 和 ⤡，用来把一个框分离悬浮到房间上方；其下一行是标题；再下面是它的制作方式。

## 精修室 <!-- #refiner -->

### 渲染之后 <!-- #after-the-render -->

![精修室：录音在右边，各步骤排成一行](guide/studio-post.png)

在右边选一段录音；工具作用于它，或它的某条分轨。右侧一栏放着 **在这里精修过的录音**，最近精修的在最前（*收藏* 旁边的 *已精修* 可切换为全部录音，以便开始新的），重新加载后房间会回到正在精修的那段录音。

由一段录音生成的一切都挂在它的 **树** 上（*由这个录音生成*），最新的在上面：先是 **原版**，带播放器和 FLAC，然后是每个分支，都可以播放，也可以作为下一步的来源。正在运行的东西会显示在你看的地方：房间的标题栏、该步骤自己区块的顶部，以及它标签页上跳动的点。每个步骤的区块列出它为这段录音生成的东西（*在这里生成的*：点击即可在树中找到），打开的步骤会点亮它自己的分支。

**全部比较**（在原版那一行，或任何分支上的 *比较*）会像 SUNO 切换版本那样，把每个版本放进同一个播放器：原版、去嗡声版、各个重制母带、各个超分、各条分轨。点击另一个版本或按它的编号（1–9），会 **从同一秒** 开始播放；空格播放和暂停，← → 移动五秒，Esc 关闭。其他录音中的同一段音乐也会排在原版之后：用另一个 VAE 或声音种子的重新渲染，各以其 VAE、种子和制作时间命名；你不喜欢的录音会被略去。

### 导入音轨 <!-- #import-a-track -->

来自任何地方的 WAV、FLAC、MP3…：它会成为资料馆里的一段录音（48 kHz，24 位），标为 *导入的*，可以进行分轨、重制母带等。歌词可选；歌词检查会与之比对。

### 各个步骤与处理链 <!-- #the-steps-and-the-chain -->

![处理链和各个步骤](guide/post-steps.png)

**处理链** 一次运行多个步骤：*去嗡声 → 超分 → 分轨 → 重新母带 → 超分*，然后可加 *瑕疵*、*频谱*、*歌词* 中的任意一个。分轨从去嗡声（并超分）后的录音中分离，重制母带再把它们混合，所以它的预设和去齿音在处理链中也起作用；第一次超分让分离器听到整首歌，最后一次重绘分轨和重制母带留下的高端（20 kHz 以上的嘶声，22 以上几乎什么都没有）。除非你另选，分轨为四条。逐个来看：

1. **频谱**：频谱图、平均频谱、频段能量；叠上另一段录音以便比较。
2. **瑕疵**：一个挥之不去的音、高频中 VAE 的 25 帧嗡声、咔嗒声、削波、断音、自相抵消的立体声。点击某个时间会从那里播放。
3. **去嗡声**：YuE2 的解码器以每帧 1920 个采样、每秒 25 帧来写声音，高频随之颤动。这一步去掉 2 kHz 以上与该帧时钟同步的成分。80 % 是耳朵的选择；100 % 会让起音变薄。
4. **歌词**：Whisper 聆听，并把听到的内容与你的歌词逐分钟比对；*给歌词行定时* 用于卡拉 OK 计时。在人声分轨上它能听到不带音乐的歌词。
5. **分轨**：四条分轨（人声用 BS-Roformer，然后鼓、贝斯和其余部分用 htdemucs_ft；伴奏也有），或人声 + 伴奏。*来源* 是录音本身，或它去嗡声、超分后的文件，每个来源各有一组；你的 DAW 拿到的是每种的最新一组。
6. **重新母带**：混合分轨，或直接用录音；清理、去齿音，可选从 440 → 432 Hz 重新调音、响度（LUFS）和真峰值。每次运行都是一个新分支。预设和去齿音作用于混合前的分轨：以录音或任何单个文件为来源时它们关闭，在处理链中分轨时它们起作用。
7. **超分**：UniverSR 重绘频谱的高端；截止频率以下原版逐个采样保持不变。在重制母带上（处理链的最后一步），如果新的高端超过重制母带的真峰值上限，整个文件会被压低。

## 画室 <!-- #artist -->

作画的房间：为每段录音画封面，为它的视频画 16:9，为短视频画 9:16，可以从你的文字、你的一张图片，或两者出发。左边是表单，中间是舞台，右边是图库。

### 为你的歌作画 <!-- #pictures-for-your-songs -->

用句子写下你为这首歌看到的画面：Krea 2 Muse 和 Qwen-Image 把提示当作描述来读，而不是标签列表。先写画面里有什么，再写光线、色彩和媒介（油画、墨水、照片），不想要文字时以 *no text* 结尾。**来自录音** 会把手头录音的封面所用的提示放进提示框，或者用它的标题和风格生成一个，作为起点。

**画幅**：封面用 **1:1**（1280 × 1280），视频用 **16:9**（1920 × 1080），短视频用 **9:16**（1080 × 1920）。一次按下的各画幅共用同一个种子，所以作为一个系列产出：同样的场景、同样的色彩，各自为自己的画框构图，而不是一张图切成三种。**变体** 也会画接下来的种子（种子、种子 + 1、…），每个都画全部画幅。

**种子**，旁边是它的模式：**随机**（−1：每次按下一个新种子，字段留空）、**随机，固定**（立刻放入一个随机种子并保留）、**固定**（写下的那个）、**下一个** 和 **上一个**（按下之后，字段越过变体用过的种子）。在字段中输入数字就是那个种子（随机变为固定）；清空字段则每次按下一个新种子（固定变为随机）；⟲ 恢复为随机。用你喜欢的图片的种子可以再画一次：每次运行都会显示它的种子，**放进表单** 会把它连同提示一起带回。

**三栏**：左边是提示及其参数，中间是舞台（正在绘制的运行在那里显影，进度条横贯顶部；否则显示你选中的图片，按钮在下方，指针在图片上时，运行的数据和提示以提示框的形式显示在旁边、图库的上方），右边是图库；拖动它们之间的边可加宽一栏（键盘 ← →，双击恢复原宽度）。栏中的选项随之伸展，不会比画师的名称更窄。窗口高度在 920 px 以上时，整个房间都能放下：页面不动，表单和图库各自滚动，“绘制”那一行停在表单底部。

**实时预览**（默认开启）：正在绘制的图片位置会显示它的每一步，从噪声到图片，以八分之一的尺寸、不经过解码器显示，所以几乎没有开销；关闭时，该位置等待完成的图片。舞台顶部横贯的进度条跟随运行，一张接一张、一步接一步。

**同时两次运行**：一次运行进行时，**绘制** 会请求下一次，它在后面等待（也可按 Ctrl+Enter）；运行时“绘制”旁的 **停止** 会结束正在绘制的那次（否则让等待的那次离开队列）；它已完成的图片会保留。

### 画师们 <!-- #the-painters -->

**Krea 2 Muse**（Stable Yogi 出品），Krea 2 Turbo 的微调（Krea 2 Community License）：显卡有 12.5 GB 空闲用 **Q4**，有 18.5 GB 用 **Q8**（更精细）。作为 Turbo 模型，它不用引导、以自己的少数几步作画：在 RTX 3090 上 1:1 每张约 35 秒，16:9 或 9:16 约 47 秒，加载每次按下约多 25 秒。

**Qwen-Image 2512**（Apache-2.0）来自 **Q4**（15.5 GB 的显卡）或 **Q6**（20 GB）的 GGUF，或它的 **fp8 微调**（22.5 GB：ComfyUI 的单文件放入 `artwork/Qwen-Image-2512/checkpoints/`，在画师下方选择）；用 Lightning 每张约半分钟，之前要加载一两分钟。**Qwen-Image 2.1** 采用 Qwen 的研究许可证（仅限研究和评估：不能用于你出售的封面），可以根据文字作画，也能按提示中的文字编辑参考图；遮罩和 *向外扩画* 需要 Krea 2 或 Qwen-Image 2512。 在既装不下它的文本编码器、也装不下画师的显卡上（16 GB 的显卡，或设了更低 VRAM 上限的显卡），两者都从内存流式加载：在 3090 上设 15.5 GB 上限时，从文字绘制 135 秒、峰值 4.1 GB，编辑 129 秒、7.9 GB。

每个画师只有在其文件就位时才显示；其他的在画师下方列出名称。**引擎 → 模型与 LoRA → Qwen 画师** 可以下载带 Lightning 的 Qwen-Image 2512 Q4（31 GB）或 Q6（34.5 GB），以及 Qwen-Image 2.1（33.1 GB），每个都会先询问并说明大小（2.1 还会说明许可证）。从终端：`heresy/fetch-heresy.sh --qwen 2512-q4`。画师下方的 **获取画师和适配器…** 在房间里直接列出工作室可以为画室下载的内容：Krea 2 Muse、Qwen 画师、四个 Qwen-Image 2512 的 fp8 微调（Jib Mix Qwen、IntoRealism Qwen、Real-Qwen-Image 和 2512 本身，各 20.4 GB，经作者许可共享在工作室的模型仓库中）和七个适配器，各附大小，已有或 **下载**。

**哪块显卡作画**：一次按下会像录音的封面图和分轨那样，在实验室的队列里等待有空间的显卡；等待期间 **移出队列** 可以撤回。没有别的东西使用的显卡，会接受需求不超过其内存减 512 MiB（CUDA 运行时自己的那份）的运行；在用的显卡在空闲内存满足需求时接受。这里没有任何显卡能完整容纳的 Qwen-Image 2512 或 Krea 2 Muse 画师，会改为从内存流式加载它的块：放得下的块留在显卡上，其余在需要时调入，图片完全相同，只是慢了总线掩盖不了的那部分（24 GB 显卡上带四个适配器约慢六分之一；所有块都流式加载时，Q4 占用显卡 2.2 GB，所以 8 GB 的显卡也能画）；其他任何显卡都容纳不下的画师会被立即拒绝，并给出数字和放得下的画师。Qwen-Image 在画师到来之前用它的文本编码器（Qwen2.5-VL-7B，15.5 GB）读取提示：显卡上空闲空间够就在显卡上，否则在处理器上；两种方式图片都一样。

**内容过滤**：无论哪个画师画的，每张图片都要通过 Krea 2 许可证要求的过滤器（工作室对所有画师的规则）：被它标记的图片不会保留，运行会说明。

### Lightning <!-- #lightning -->

**它是什么**：Lightning（lightx2v，Apache-2.0）是一个适配器，教 Qwen-Image 2512 不用引导、用很少的步数作画：把模型自己漫长的引导过程蒸馏成 8 步。它的文件位于 `artwork/Qwen-Image-2512/lightning/`（`Qwen-Image-2512-Lightning-8steps-V1.0-bf16.safetensors`，0.85 GB），随 Qwen 画师一起下载。

**工作室如何加入它**：开启 Lightning 时，画师把它作为你自己的 LoRA 之下的又一个适配器加载，按它的强度：GGUF 的 Q4 和 Q6 用 **1.0**（它所蒸馏的基座，按作者给出的 8 步），fp8 微调用 **0.55**、12 步（微调已经偏离基座，满强度的 Lightning 会把它拉回去；这是 Viktor 自己在 ComfyUI 中的设置）。调度变为 Lightning 自己的：无论尺寸都用 log 3 的偏移，与训练时一致。引导关闭（true CFG 1）：每步模型运行一遍。

**关闭时**，画师走 2512 自己的路：默认 30 步（10 到 60），**引导** 4（带空负向提示的 true CFG：每步两遍）。六十遍对八遍：作画本身约慢七倍，加载时间相同，换来成品级写实的细节和光线。

**它的默认值**：GGUF 的 Q4 和 Q6 用它作画（草稿，较小的显卡）；fp8 微调不用它，除非你开启（成品级写实）；录音自己的封面图用它画（*引擎 → 封面图*）。背后的规则：Lightning 用于草稿和封面，不用于专业写实。

**开关**：在“采样”中，旁边是它的强度；开启时步数为 4 到 16，引导隐藏；关闭时显示引导。没有它的文件就没有开关，2512 按自己的方式作画。Krea 2 Muse 没有这个开关：作为 Turbo 模型，少数几步是它自己的。强度为每个画师分别保存；你的适配器合计（下面的 *合计*）不计入 Lightning。

**代价**：在 RTX 3090 上以 1328 × 1328，带 Lightning 的 Qwen-Image 2512 用 Q4 每张约 30 秒（峰值 14.3 GB），Q6 约 32 秒（17.6 GB）；fp8 微调在 0.55、12 步时 37 秒（21.0 GB）。用 Lightning 画一段录音的封面，连同加载和提示约一分半钟。

### 采样器与调度 <!-- #samplers-and-schedules -->

画师下方的 **采样** 默认收起，其数值显示在摘要中：步数、采样器和调度，为每个画师分别保存；**重置** 恢复该画师自己的设置。步数：Krea 2 以及带 Lightning 的 Qwen-Image 2512 为 4 到 16；其他为 10 到 60；超出范围的数字停在边界。表单的时间估计会计入采样器的遍数。

**采样器**：每一步模型都会指出图片在哪个方向；采样器决定怎样走过去。

- **Euler**：每步一遍，最朴素的一步；它是参照，也是蒸馏 Lightning 时所用的。
- **Euler SDE**：每步加入少量新噪声的 Euler：颗粒更多，忠实度略低。
- **ER-SDE**：三阶随机求解器（ER-SDE-Solver-3），每步一遍，保留前两步：同样时间下比 Euler 更精细。
- **RES 2s** 和 **RES 3s**：改进的指数求解器的单步方法，每步两遍和三遍，每遍之后放回一半噪声；它们的 **ODE** 孪生版不放回噪声，因此一个种子画一张图，最接近精确路径。
- **Heun++**（heunpp2）：能用时每步三遍，然后两遍，最后一遍。
- **指数 Heun**（exp_heun_2_x0 及其 SDE 版）：二阶指数方法，每步两遍；SDE 版会放回噪声。

每步两遍或三遍的采样器，在相同步数下耗时是 Euler 的两到三倍；在 Lightning 的 8 步中，高阶方法改变的是细节，而不是构图。对照一个玩具流在 8 步下的精确路径，它们按阶数排序：Euler 0.138、Heun++ 0.111、指数 Heun 0.084、RES 2s 0.058、RES 3s 0.046（误差：越低越接近）。

**调度** 决定从全是噪声到没有噪声的过程中，步数花在哪里：

- **Simple**：在画师自己的时间里均匀分布，保留其偏移。
- **Karras** 和 **Exponential**：在噪声少时用更多步，为了细节。
- **Beta** 和 **Beta 57**：两端密，中间疏（Beta 57 用 0.5 和 0.7）。
- **KL optimal**：Align Your Steps 找到的最优间隔。
- **SGM uniform**：时间上均匀，去掉最后一步。
- **Bong tangent**：两段反正切斜坡，从全是噪声到一半，再从一半到没有。

**两个矩阵的结果**（在测试实验室中画了 54 张，同一提示，同一种子）：在 Krea 2 Muse 上每种采样器和调度都画出了完整的图片。在 Qwen-Image 2512 上，**带 Lightning 时 Karras、Exponential 和 KL optimal 可能把主体画两次**（要一座灯塔却画了两座）：用 Lightning 时请选 Simple、Beta、Beta 57、SGM uniform 或 Bong tangent。**不带 Lightning 时，Euler SDE 会把 Qwen 画得柔软朦胧**：Euler、ER-SDE 或 RES 能保留细节。适用时表单会提示这两点。

**来源**：根据各方法的论文和 ComfyUI 的公式为工作室编写（GPL-3.0，工作室的 AGPL 可以纳入）；RES4LYF 的只读了其中的数学，因为它的许可证禁止商业服务：这里没有它的任何代码；Heun++ 出自 Carzit（MIT）。

### 区域 <!-- #regions -->

*采样* 下方折叠的 **区域**：画面中最多三个部分，各有一个位置（一半、三分之一、四分之一或中间；旁边的小图显示在哪里）和自己的文字。每一步都会针对每个区域再询问画师一次，用提示词加上该区域的文字，再按边缘柔和的框把结果混合起来，与 Latent Couple 的做法相同；画面其余部分只跟随提示词。所以提示词描述整个场景，区域说明那里有什么：*雪林空地上的两只动物*，然后左半边是 *一只红狐狸*，右半边是 *树桩上的一只白色猫头鹰*。每个区域每一步要多算一整遍（3090 上 16:9，Krea 2 Q4：不加 48 秒，两个区域 137 秒；Qwen-Image 2512 fp8：141 秒和 281 秒）。保存在此浏览器中；没有文字的区域不会发送；**再来** 使用该次运行自己的区域绘制。适用于 Krea 2 和 Qwen-Image 2512；Qwen-Image 2.1 用文字编辑，不使用区域。

### 题字 <!-- #lettering -->

*区域* 下方折叠的 **题字**：标题及其下方的第二行（艺人、专辑），作为画面的一部分写进去，而不是叠在上面。它的文字放在专门的栏里，从不放进提示词：**标题**、**第二行**、**字体**（用文字描述样子；留空则为暖金色古典衬线大写）、**位置**（顶部、中间、底部）以及 **方式**：*随画面绘制*（Krea 2 Muse、Qwen-Image 2512 或 2.1 绘制提示词的场景并写入文字；样本提示词中的“No text”会被去掉）或 *在参考图上*（Qwen-Image 2.1 按文字在完成的画上题写，其余保持不变；画上的 **题字** 会把它设为参考图并打开此栏）。画师会写错很少见过的词（“RUOCH STUDIO”），所以每幅画都由听者（Qwen2.5-Omni，每幅约 5 秒）回读，写错的换一个种子重画，最多三次：保留第一幅写对的，其余移入该次运行的 misspelled/ 文件夹。每幅画旁的标记说明读到的情况：✓ 与要求一致，⚠ 每次尝试都写错（提示中给出读到的文字），? 未回读（本机没有听者）。在 3090 上，Qwen-Image 2.1 为一幅方图题字用时 118 秒；Qwen-Image 2512 fp8 (不用 Lightning) 连同加载画出一幅带字的图用时 230 秒。也能写西里尔字母（大写更可靠）。保存在此浏览器中；**再来** 用该次运行自己的文字题写。

### 适配器 <!-- #adapters -->

画师下方的 **LoRA**：其类别（Krea 2、Qwen-Image 2.1、Qwen-Image 2512）的适配器，最多四个，各有强度（0 到 1.5）；点击它的某个触发词会把它放入提示。**添加…** 打开库：左边是文件夹，然后是带图片的卡片和搜索。适配器放在工作室的 `artwork/loras/<family>/`（`krea2`、`qwen-image-2.1`、`qwen-image-2512`、`sdxl`）中：其中的任何文件夹都会成为分组，文件旁同名的图片（`NAME.jpg`、`NAME.png`、`NAME.preview.png`）会显示在卡片上。按基础模型（Krea 2、Qwen）从 Civitai 获取，把 `.safetensors` 放进去；**在 Civitai 上查询** 只发送每个文件的 SHA-256，其他什么都不发，并把回应保存在旁边（`NAME.civitai.info`：名称、基础模型和触发词，没有图片时还有第一张被评为安全的图片）。ComfyUI 的 LoRA Manager 或 Stability Matrix 写在文件旁的内容也会被读取。为其他模型制作、触及不到画师任何层的适配器会停止运行并说明。在适配器那一行右键会 **静音** 它：它带着强度留在列表中，但离开运行（**取消静音** 恢复）；强度为零的适配器也不会加载。作者允许共享的七个适配器来自 **获取画师和适配器…**。

**合计**：有两个以上适配器时，下方的条在创作室同样的路上显示它们强度的总和：1.2 以内绿色，1.8 以内琥珀色，超过为红色。叠加的适配器会相加，超过约 1.8 时，无论每个多么克制，图片都会烧坏（色彩和边缘过度）；这些区间是图片的初步标准，要凭眼睛调整。拖动这条可以一次移动全部，每个按其原位置成比例移动。

### 作为基础的图片 <!-- #a-picture-to-paint-from -->

**参考图**：以图生图方式作画所依据的图片：把一张拖到提示下方它的位置、粘贴一张（Ctrl+V）、选择一个文件，或用 **作为参考** 取舞台上的图片。**允许改变多少** 表示作画从离它多远处开始：0.3 几乎保持原样，0.6 保留构图、改变质感，0.9 用它的光线和色彩画出提示中的场景，1.0 重新作画。每个画幅都被图片覆盖，并从中间裁出；**再来** 从这次运行自己的图片作画；✕ 又从噪声开始作画。

图片下方的 **用途** 说明怎么用它：*从它开始绘制*（如上，用表单中的画师，程度由 *允许改变多少* 决定）、*用文字编辑* 或 *只取它的风格*，后两者都由 Qwen-Image 2.1 完成，仅在它存在时可用（否则不可选）。用文字编辑时，场景保留，提示词说明要改什么（*同一座灯塔在下雪的冬夜*：雪落在该落的地方，塔和岩石都保留了）。只取风格时，用图片的技法、笔触、配色和光线画出提示词自己的场景，原图的题材一点也不保留（油画灯塔以它的笔触画出了 *月光下雪林中的一只红狐狸*）。两种情况下，无论表单中是哪位画师，这次运行都属于 Qwen-Image 2.1：表单的模型、采样、适配器、蒙版和画布都不会发送，并适用它的许可（仅限研究和评估）。在 3090 上每张约 2 分钟。

旁边的 **遮罩…** 在图片上涂出要重画的部分（涂、擦除、画笔、反转、清空）：其余部分与原来完全相同，即局部重绘。**向外扩画** 把整张图片放在每个画幅的中间，重新画出边缘（把方形封面扩成 16:9 或 9:16），即外扩绘制。**录音的封面** 取右侧所选录音的封面。有遮罩或 **向外扩画** 时，图片下方有四个选项：**扩张**（遮罩扩大或缩小若干像素）、**边缘**（边缘的柔和程度）、**柔和**（柔和重绘，类似差分扩散：边缘为灰色处图片只在最后几步改变，因此没有接缝）和 **颗粒**（保留部分吸收多少新颜料，把它的颗粒和光线与新画的缝合；0 表示完全保持）。

**遮罩…** 旁边的 **画布…** 打开一个像 InvokeAI 那样的画布：每个画幅的框是顶部的一个标签，标明将如何绘制（**以它为基础**：图片覆盖整个框，运行按要求的强度以图生图方式绘制；**四周**：图片空出的框的部分在其四周补画）。在画板上，**移动**（V）拖动图片，拖动某个角则在保持对角不动的情况下缩放；**画笔**（B）和 **橡皮**（E）在其上绘制局部重绘遮罩；**抓手**（H，或按住空格）移动画板；滚轮缩放，Alt+滚轮以指针为中心缩放图片，方向键微调。右侧是图层（带 **反转** 和 **清空** 的遮罩，以及仅在画板上有不透明度的参考图）和它的数值位置（宽度，以及占框比例的 X、Y）；顶部有 **适合窗口**、**填满**、**居中** 和 **全部相同**（在其他框中图片像素大小相同），以及撤销和重做（Ctrl+Z）。**完成** 把位置连同参考图和遮罩保存在表单中；强度下方表单会说明每个画幅如何放置，✕ 把它移出画布。

### 舞台与图库 <!-- #the-stage-and-the-library -->

点击一张图片会把它连同下方的运行放到舞台上；点击舞台上的图片（或双击一张图片）会以它自己的画幅覆盖页面打开（← → 在该次运行中浏览，或在从图库打开时在图库中浏览；Esc 关闭），带有 ★、**放进表单**、**设为封面** 和 **下载**（PNG，原尺寸）。

**运行或图库**：运行视图显示每次按下“绘制”的结果及其提示和种子，最新的在上；图库把所有运行的所有图片放在一个网格中，最新的在前，可按画幅（1:1、16:9、9:16）或星标（图片上的 ☆ 加星）筛选，有三种尺寸，用均匀的方块显示：等宽的列，每个方块大小相同，每张图片完整地放在其中。

**比较**：舞台上的 **比较…**，然后在图库中选另一张：两张叠放在一条可拖动的分隔线下（← → 移动），或并排（S）；X 交换，Esc 关闭。**Ctrl**（或 ⌘）**+ 点击** 选择图片，**Shift + 点击** 选择一个范围：然后图库的工具栏可以一次给它们加星或移到回收站（Esc 取消选择）。

**图片的菜单**：在任何图片上右键（运行中的、图库中的、舞台上的、覆盖页面的那张）：**覆盖页面**、**放到舞台**、**放进表单**（它的提示、种子和画幅）、**全部放进表单**（还包括它的画师、微调、采样和适配器：“绘制”会再画一次这张图）、**作为参考**、**比较…**、**设为封面**、**超分**（2K 或 4K，即它们给出的尺寸）、**加星**、**选中**、**复制提示词**、**复制种子**、**下载**、**在新标签页打开文件**、**它的运行**（运行视图，其卡片高亮）、**移到回收站**。正在舞台上显影的运行没有菜单。在覆盖页面时，菜单位于图片之上，打开期间接管按键：Esc 关闭菜单，再按一次 Esc 关闭图片。

### 超分 <!-- #upscale -->

舞台上的 **超分…** 把图片放大到 **2K** 或 **4K**：长边 2560 或 3840 px（方形封面为 2560² 或 3840²，16:9 为 2560×1440 或 3840×2160），使用在展开的那一行中选择的超分器（ESRGAN、DAT、HAT、SPAN 及其同类，由 spandrel 读取）（选择会保存；有 4x_Nomos8kDAT 时排在最前）；每个按钮的提示说明它给出的尺寸，已经这么大的图片对应按钮会关闭。模型按尺寸需要运行若干次（最多两次），结果调整到精确尺寸。大图作为一次独立的运行放在原图旁边，在 3090 上不到一分钟；**再来** 再次超分同一张图，也许换一个模型。超分器放在工作室的 `artwork/upscalers/`（`.pth` 或 `.safetensors`，可以有文件夹）；OpenModelDB 列出了数百个：注意每个的许可证。

旁边的 **第二遍…** 会把图片放大后重新绘制，就像 Viktor 的 ComfyUI 工作流在第一遍之后所做的那样：把图片放大 **×1.5** 或 **×2**（与他的一样用最近邻），再由同一次运行的画师、微调模型、适配器、提示词和种子从半途开始重新绘制（*允许改变多少*：0.3 保留画面并添加细节，0.5 打磨质感，0.7 重画形体）。当表单使用同一位画师时，步数、采样器、调度和 Lightning 取自表单，否则取自该次运行：他的配方给第二遍很多步数，并且不用 Lightning。1920×1080 的 16:9 会变成 3840×2160。在 3090 上实测：Krea 2 Q4 绘制 2560² 用时 86 秒（峰值 14.5 GB），Qwen-Image 2512 fp8 绘制 3840×2160 在 12 步加 Lightning 下用时 220 秒（22.9 GB）。不适用于以文字编辑的 Qwen-Image 2.1；不能与蒙版或画布同用。 同一行中的 **附加噪声**（起初为 0.6，与他的相同）以及参考图 *允许改变多少* 下方的附加噪声（起初为 0），就是他工作流中的 InjectLatentNoise：在从图片开始绘制之前给它加上新的噪声；0.3 带来新的颗粒和细节，超过 1 图片的形体开始瓦解。

### 录音的封面 <!-- #a-cover-for-the-take -->

方形图片有 **设为封面**：它会成为手头录音（在右边选一段）的封面，出现在其卡片、播放器和 MP3 中。原来的封面保存在录音旁边（`artwork-removed/`），与重画时的保存方式相同；A/B 对中的另一个字母若没有封面，也会得到这张新封面。

**录音自己的封面图**（在其菜单中、在资料馆中为一段或多段录音 *绘制封面图*）由 **引擎 → 封面图** 中的画师绘制：按显卡决定（Krea 2 Muse Q4：16 GB 显卡上整个运行，更小的显卡上从内存流式加载其块），或由你选择：Krea 2 Muse Q4 或 Q8，以及这台机器上已有的 Qwen 画师：Qwen-Image 2512 Q4 或 Q6 及每个带 Lightning 的 fp8 微调，Qwen-Image 2.1 并说明其许可证（不能用于出售的歌曲）。所选的微调不在了时，会让位于按显卡的选择，封面图会注明是谁画的。

### 画室的回收站 <!-- #the-artist-s-trash -->

运行保存在工作室的 `artist/` 文件夹中。运行上的 **回收站** 把它移到 `trash/artist/`；舞台上的 **回收站** 把一张图片放到一边。运行和图库旁的 **回收站** 视图先显示放到一边的图片，每张带 **恢复** 和 ✕，以及 **全部恢复**；然后是回收站中的运行，每个带 **恢复** 和 **永久删除**；标题栏中的 **全部清除** 删除它显示的全部内容。每次删除都会先询问，且无法撤销。

资料馆一栏中“不在视野内”之下的 **回收站（封面图）** 把收起的图片以图块排列（点一下图块即勾选）：回收站中画室的运行、放到一边的图片，以及从录音上取下的封面（因重画、因移除、因新封面），每项带图片和大小。勾选它们以恢复（封面回到它的录音，录音现在的封面替它保存起来），或在询问后永久删除；什么都没勾选时，**清空封面图回收站**。冻结工作区的封面保持不变。

### 画室的日志 <!-- #the-artist-s-log -->

### 封面图：谁来画，画不了什么，换一个画师 <!-- #artwork-what-draws-it-what-it-cannot-another-painter -->

**谁来画。** 一个小语言模型（Qwen3-4B）读取录音的风格和歌词，写出一条图片提示，主体放在最前；Krea 2 Muse 画出它（1024 px），整个放不下的地方从内存流式加载其块（*引擎 → 封面图*）。录音以某种乐器命名时（某种乐器的样例），工作室会同时说明这件乐器的样子和它的出处，Omni（聆听者的模型）会看这张图：找不到这件乐器时，它会根据看到的重写提示，画师再试一次，最多三张。在 16 GB 的显卡上每张约半分钟。在那里选的 Qwen 画师会用 Lightning 作画：以 1328 px 绘制，按 1024 保存。

**画不了什么**（直说的免责声明）：画师画它认识的东西。它从未按名字见过的乐器（杜杜克、马头琴、口簧琴、水晶颂钵…）会画成一种猜测：一根木管、一把小提琴、几只厨房的碗。Omni 在三张图里都没找到乐器时，图片会在叠加层和乐器速查表中标为 **≈ 推测**。封面图是录音的情绪，不是乐器的参考图：想知道一件乐器长什么样，去查一查。

## LoRA 训练室 <!-- #lora -->

训练器已在我们自己的歌曲和嗓音上验证，目前暂定为 90 % 的完成度：你的素材集和使用场景与我们不同，所以请告诉我们效果如何（仓库中的 *Trainer report*：素材集、模式、设置、你听到了什么）。

### LoRA 教会 YuE2 什么 <!-- #what-a-lora-teaches-yue2 -->

LoRA 是覆盖两半的小型适配器。**风格主要来自声音部分；跟随歌词来自音乐部分**，而音乐部分很快就会把小数据集背下来（它的损失降向 0）。类型：

| 类型 | 数据 | 学到什么 |
|---|---|---|
| **风格** | 20 首以上同一种声音的歌 | 流派、制作、一支乐队的声音 |
| **嗓音** | 一个嗓音，唱的或说的：演唱（最好是无伴奏）、朗读、有声书 | 一种音色 |
| **语言** | 许多嗓音，准确的歌词 | 一种语言的吐字 |
| **艺人** | 庞大而多样的作品集 | 以上全部 |

**嗓音适配器可以从任何形式的嗓音中学习**，不只是演唱：朗读和有声书也行。在这里测得（05.10.2026）：用一位演员的朗读训练的适配器用他的嗓音说话，唱歌时也带着他的音色。这样的适配器要按类型命名（男低音、男中高音、女低音…），绝不用人名：`lab/voice_kind.py` 根据说话音高测量数据集的嗓音。

![LoRA 训练室：一次运行的遥测](guide/studio-train.png)

### 为什么要自己的适配器 <!-- #why-your-own-adapters -->

一个裸的开源模型，无论多强，在乐器、风格和嗓音上仍然不够：它只知道训练时听过的东西，而你的声音很少在其中。你自己的适配器能补上这个差距；它们是专业音频与音乐战士的铠甲。最稳妥的一步：收集你最好的曲目——在 SUNO 上做的（付费方案下归你所有），或任何你拥有版权的其他来源——为每首配上准确的歌词，用它们训练一个 **风格** 适配器。这样 YuE2 写出的就是你的声音，而不是接近它：你的乐器、你的编曲、你的制作。再加一个你想要的歌手的 **嗓音** 适配器，歌曲就会用那种音色来唱。用你自己二十首歌训练出的风格，比任何提示词都更能把模型推高。

### 1 素材 <!-- #1-material -->

把一个歌曲文件夹放进 `datasets/raw/` 并选中它。选择哪些音轨加入，给每条配上歌词（若有同名文件会在旁边自动找到），需要的话再配一个它自己的风格。默认略过短于 30 秒的音轨；长的没问题（音乐部分会在整首歌上训练）。

**嗓音**：*测量嗓音* 会听文件夹中最多十二条音轨，对说话声给出男声或女声及声部（男低音、男中音、男中高音、男高音；女低音、女中音、女高音）和说话音高，并按已发布嗓音适配器的命名方式（`voice-ru-m-baritenor-117`）为由它们组成的数据集提议一个名称：不用任何人名。对歌声，它给出演唱的音域，把嗓音判断留给你的耳朵。仅凭音高无法判断时（说话 140–175 Hz），选 ♂ 或 ♀ 再测一次。这是测量得出的草稿：由耳朵决定，YuE2 之后唱出的嗓音可能偏高或偏低。

### 2 数据集 <!-- #2-the-set -->

**触发词**（一个不常见的词，例如 `fosforida`）以后可以按名称唤起这个风格；**共用的风格行** 写出听到的内容。*制作数据集* 会写出 `datasets/prepared/NAME/`：48 kHz 音频和每条音轨的描述。

**聆听者**（Qwen2.5-Omni，在任何有约 8 GB 空闲的显卡上）会听每条音轨并起草其标签；由你修改，然后 *写入描述*。无论大小它都只是草稿：要读一读。

### 3 训练 <!-- #3-train -->

![一种类型、参数、一块显卡](guide/train-knobs.png)

选择在第 2 步中制作的数据集，然后选一种 **类型**：它会按你要教的内容设定参数（列表下方的表格），每个参数都可以在 *训练* 之前修改。表单逐项说明：

- **类型**：风格、嗓音、语言或艺人。
- **运行名称**：这次运行的文件夹（`training/NAME/`）以及它的适配器名称（`loras/NAME/NAME-eNNN`，会立即出现在创作室的 LoRA 中）。一个名称只属于一次运行：被占用时页面会要求换一个。
- **训练室**：**Ruach Studio**（工作室自己的，在未量化的 bf16 权重上；它自己制作数据集的潜在缓存；直接模式或带乐谱，可用原曲或分离后的歌）。逐行移植自 Ostris 的 **AI-Toolkit**（MIT），在同一数据集上与它的曲线逐轮次一致；AI-Toolkit 本身在它能训练的一切都到了这里之后离开了工作室。
- **基础权重**：bf16 即完整模型（24 GB 的显卡），或给较小显卡用的 int8，精度稍低。基础模型的文件永远不会改变：只有适配器在学习。
- **轮数**：运行把数据集过多少遍，每轮每条音轨一次，每步一条音轨：总步数 = 数据集的音轨数 × 这个数（2016 条音轨训练 12 轮即 24 192 步）。声音部分每次随机截取音轨的 60 秒窗口来听；音乐部分从头读整首歌。
- **每 N 个轮次保存**：在每第 N 个轮次结束时保存一个适配器，每个都可以试听和比较，全部保留，最新的旁边保存优化器的状态（停止的运行会保留已学到的）。
- **秩**：适配器有多宽；它占权重的比例和大小在字段的提示中（每个秩的代价以及哪种用途选哪个：见下文）。
- **学习率**：声音部分每一步的大小（AdamW，整个运行相同）；音乐部分的学习率是它乘以 **AR 速度**。各类型保持 0.0001；减半更温和，适合在大数据集上长时间运行；更高学得更快，也忘得更多。
- **AR 权重**、**AR 锚点（KL）**、**AR 速度**：音乐部分的三个参数，见下文。
- **模式**：**直接** 用于在直接模式下做的歌；**完整（乐谱）** 和 **旋律** 用于在这些模式下做的歌，还会教音乐部分先写乐谱，乐谱在训练前由引擎从每首歌扒出来；一半的步骤不带乐谱，因此不会忘掉直接模式。**分离人声和音乐**：每首歌先由工作室的分离器分成人声和音乐（每个数据集一次，每首几分钟），音乐部分还会只从歌词学人声、只从标签学音乐。
- 按钮下方：以往运行测得的显存，以及现在哪块显卡足够空闲。

| 类型 | 秩 | 步数 | AR 权重 | AR 锚点 | AR 速度 | 用途 |
|---|---|---|---|---|---|---|
| **风格** | 32 | 1500 | 0.5 | 0.2 | 0.5 | 一种声音：流派、制作、一支乐队的声音 |
| **嗓音** | 16 | 1500 | 0.3 | 0.3 | 0.5 | 一种音色：音乐部分保持接近基座 |
| **语言** | 32 | 3000 | 1.0 | 0.1 | 1.0 | 吐字：音乐部分就是要改变 |
| **艺人** | 32 | 3000 | 0.7 | 0.2 | 0.7 | 以上全部 |

### 秩与其他参数 <!-- #rank-and-the-other-knobs -->

**秩** 是适配器对每个矩阵所做改变的宽度。LoRA 调整 YuE2 的 224 个矩阵，每一半 112 个；每个宽 2048，深 28 层，每一半 14.1 亿个权重。在这些形状上测得的各秩代价：

| 秩 | 占所调整权重的比例 | 文件，每一半（bf16） |
|---|---|---|
| 16 | 1 % | 29 MB |
| 32 | 2 % | 59 MB |
| 64 | 4 % | 117 MB |
| 128 | 8 % | 235 MB |
| 256 | 17 % | 470 MB |

- **一个嗓音、一件乐器、一种声音**（20 到 50 首歌）：**16**，最多 32。
- **一种风格或一位艺人**（多样的作品集）：**32**。
- **包含许多嗓音的大数据集**（好几个小时，每个嗓音一个标签）：**64**，**最多 128**，仅在 64 经测量明显不够时使用。训练室在 128 停止：256 会改变它所触及权重的六分之一，超过这里任何数据集的需要。
- 基础模型的文件永远不会改变。大秩的风险在于适配器本身：满强度时它会忘记没给它看过的东西（如果从说话声学习，就会忘记唱歌）。
- **轮数**：音乐部分很快就会把小数据集背下来（损失降向 0）：遥测中绿色的轮次最先要听，常常远在最后一个之前。
- **素材的采样率**：声音部分以 48 kHz 工作，音乐部分以 24 kHz 聆听。24 kHz 的录音能教会音乐部分一切，但只能教给声音部分沉闷的高端：重采样不会在原始采样率一半以上增加任何东西。要学音色，请给它 44.1 或 48 kHz。

### 音乐部分的三个参数 <!-- #the-music-half-s-three-knobs -->

每一步都分别教两半。声音部分始终学习声音：去掉音轨窗口中的噪声（流损失）。音乐部分只有在 **AR 权重** 大于 0 时才学习，这时有两股力量同时拉扯它：

- **它的功课**（ar_ce）：从歌曲开头起，逐词逐音地预测歌曲自己的令牌：吐字、乐句、旋律习惯、一首歌的形态；
- **锚点**（ar_kl）：在每个位置，训练器都会问基础模型（关闭适配器的同一个音乐部分）它会在那里写什么，并对适配器偏离它的每一步加以惩罚。

一步的损失 = 流 + AR 权重 × ar_ce + AR 锚点 × ar_kl。各参数的作用：

- **AR 权重** 决定音乐部分是否学习，以及它的功课对抗锚点的力度。为 0 时音乐部分保持为基础模型（适配器中它的那部分保持为空：全为零，已测量），适配器只是声音部分上的一种音色，锚点不起作用。
- **AR 锚点** 把音乐部分拉回基础模型，让它保留数据集中没有展示的东西：用朗读数据集训练后仍会唱歌、其他语言、跟随新的歌词、写乐谱。没有锚点时，它会随数据集漂移。
- **两者相互拉扯，起作用的只是它们的比例，而不是大小。** AdamW 按每步自己近期梯度的大小来缩放，所以乘上一个数的损失教的仍是原来的内容：0.5 配锚点 0.2，等于 1.0 配 0.4。把锚点看作权重的一个比例：十分之一让音乐部分可以移动（语言），一样大则把它留在基座附近（嗓音）。
- **AR 速度** 是音乐部分真正的油门：它的学习率是学习率乘以这个值，这是唯一能让音乐部分学得更快或更慢的参数。各类型设为 0.5（语言为 1.0）：音乐部分在声音部分获得音色之前很久，就已把小数据集背下来了。

在这里测得（10.10.2026：在 60 段朗读的数据集上 40 步，秩 16，一个种子；*移动量*：适配器对音乐部分矩阵所做改变的大小）：

| AR 权重 · 锚点 · 速度 | 移动量 | 与第一行的差异 | ar_kl，最后十步 |
|---|---|---|---|
| 0.5 · 0.2 · 0.5（风格的） | 1.32 | 同一运行再来一次：1 % | 0.257 |
| 1.0 · 0.4 · 0.5（两者都加倍） | 1.36 | 5 % | 0.262 |
| 0.5 · 0 · 0.5（没有锚点） | 1.44 | 23 % | — |
| 0.5 · 0.5 · 0.5（锚点一样大） | 1.21 | 17 % | 0.132 |
| 0.5 · 0.2 · 1.0（速度加倍） | 2.32 | 99 % | 0.443 |
| 0 · 0 · 0.5 | 0 | 什么也没学 | — |

两者都加倍，适配器改变了 5 %，而同一运行做两次是 1 %；锚点比例让它移动了六分之一到四分之一；速度加倍让它多走了四分之三。声音部分与音乐部分只共享梯度裁剪：各行之间它相差 4 到 13 %，而同一运行做两次相差 2 %。

根据你听到和看到的，该调什么：

| 何时 | 调整 |
|---|---|
| 你只想要一种音色（来自朗读的嗓音、一件乐器） | AR 权重调低，锚点一样大（嗓音的 0.3 和 0.3），或 AR 权重为 0 |
| 你想要一种语言的吐字、一种风格的乐句 | AR 权重 1.0，锚点为其十分之一，AR 速度 1.0（语言的） |
| ar_ce 很早就降到 0.3 以下：它把歌背下来了 | 降低 AR 速度，或提高锚点比例；或者听更早的轮次 |
| 适配器用训练歌曲的曲调唱新歌词，或丢失歌词 | 提高锚点比例：与权重一样大，或更大 |
| ar_kl 一直接近 0，吐字没有学到 | 提高 AR 速度，或降低锚点比例 |

### 4 遥测 <!-- #4-telemetry -->

![两半的曲线，各自下方有说明](guide/train-charts.png)

正在训练的运行显示在房间顶部，带有进度、剩余时间和两个损失。一次运行的遥测先显示进度，然后是一组方块：速度、已运行和剩余的时间、flow、ar_ce 和 **ar_kl**（音乐部分偏离基础模型多远：AR 权重为 0 时为 0）的最新值、显存峰值和显卡；然后是两条曲线：

- **声音部分 · 流损失**：声音部分对需要去掉的噪声预测得多好。它每步都会跳动（每步随机抽取一个噪声水平）：看粗线，即移动平均。
- **音乐部分 · ar_ce**：音乐部分对歌曲自己的令牌预测得多好。接近 0 时它已把歌背下来；这时更早的轮次才是更好的适配器。

把指针悬停在曲线上可读出步数、所在轮次和该处的值。**比较对象…** 把另一次运行的曲线以虚线叠加上来。**日志** 旁的按钮把两条曲线上下排列，各占满宽，或再并排。**日志** 在房间底部打开，宽度与行一致，位于服务器日志旁边。

### 最值得先听的轮次 <!-- #the-epochs-worth-hearing-first -->

![绿色：先听；✓：在 loras/ 中](guide/train-epochs.png)

每个保存的轮次都是一个标签。**绿色** 的最值得先听，是从曲线读出来的：声音损失稳定下来的第一个轮次、声音损失最低的那个，以及音乐部分把歌背下来之前的最后一个。这是一种推测；由耳朵决定。选一个轮次：**放进 loras/ → 创作室**（它会立即出现在 LoRA 中）、**移出 loras/**，或 **下载**。

> **不带乐谱（直接模式）训练的适配器，只有在直接模式的运行中才放在音乐部分。** 在完整规划中，即使强度很低，它的音乐部分也可能弄坏乐谱：在那里只给它声音部分。

### 运行 <!-- #runs -->

![每次运行一张卡片](guide/train-runs.png)

每次运行都是右侧的一张卡片：*进行中*、*全部*、*已归档*、*回收站*，可以搜索。正在训练的运行会像正在播放的录音那样亮起。卡片上的 ⋯：它的遥测、日志、归档、停止，或删除到回收站（会问你它在 loras/ 中的适配器是否一起删除）。从回收站可以恢复，或彻底删除。

## 引擎 <!-- #engine -->

### 机器 <!-- #the-machine -->

![引擎](guide/studio-engine.png)

- **服务器**：引擎在运行什么：模型、解码器、上下文、库。
- **计算**：**模型** 副本（BF16 7.2 GB、Q8_0 3.8 GB、更小的 Q6_K 和 Q5_K_M）、**显存预设**（*自动* 让上下文和 VAE 分块适配显卡；*N GB 内自动* 按该容量适配，显卡其余部分留给上面运行的其他程序（16 GB 的笔记本上为 14）；*手动* 交给你自己）、**保持模型加载**。**扫描机器** 会像新工作室在第一次启动时做的那样，说明这台机器有什么、适合什么（主干、自动的参数、画师）。
- **硬件**：显卡当前的内存；**卸载模型** 立即释放它。

### GPU：哪块显卡做什么 <!-- #gpus-which-card-does-what -->

![哪块显卡做什么](guide/engine-gpus.png)

在有多块显卡的机器上，给每块分配工作：**工作室**（合成）在一块卡上，**训练** 在你分给它的卡上，实验室的 **任务**（聆听者、Whisper、分轨、重制母带、超分）在它们自己的卡上。当一次运行在工作室自己的卡上训练时，合成会等待，页面会说明原因。只有一块卡时就是这样：先训练，再创作。为工作室换一块新卡需要重启后生效（需要时按钮会出现）。实验室的任务（包括画室）只用为它们勾选的显卡：这些卡满了时，任务会等其中一块（Whisper 转到处理器），绝不会占用没为实验室勾选的显卡。画室的运行会去它的画师从上次运行保留下来的那块卡，权重已经在内存中。

### 解码器、适配器、滑块、写作室的模型、外观 <!-- #decoders-adapters-sliders-the-writer-s-model-the-look -->

- **VAE**、**LoRA**、**滑块**：工作室找到的每个文件，附有来源和作用。
- **模型与 LoRA**：安装带来的内容，逐部分列出（额外的解码器和滑块、Whisper、分轨模型、UniverSR、LoRA），按上次运行发现的状态显示，**再次检查** 会重新查看。不完整的部分会列出缺少的内容，并有自己的 **下载**；**下载缺少的部分** 一次全部取得；中断的下载会从停下处继续。**更多模型**：另一个主干（与 Q8_0 并存的 BF16）、风格聆听者、画室的画师、训练室的基座，各有其变体和大小，已有的变体会注明，每个都会先询问并说明大小。新的主干、解码器或滑块会在引擎下次启动时生效（**重启引擎**）；新的 LoRA 立即可用。
- **封面图**：由谁画录音的封面图：按显卡决定（Krea 2 Muse Q4：16 GB 显卡上整个运行，更小的显卡上从内存流式加载其块），或选定一个：Krea 2 Muse Q4 或 Q8，以及这台机器上已有的 Qwen 画师（Qwen-Image 2512 Q4 或 Q6 及每个 fp8 微调，带 Lightning；Qwen-Image 2.1 并说明其许可证）。
- **写作室**：本地聊天服务器的地址（vLLM、LM Studio、Ollama），*测试连接*。
- **外观**：22 个主题（为工作而选：清晰而安静）、圆角、三种字体（正文、标题、数字）。
- **服务器日志**：完整日志；**关于**：工作室所依托的每个项目，附链接。
- **更新**：GitHub 上 Ruach Studio 的版本与当前版本的对比：多久检查一次（每天、每周、每月、从不），是否包括候选版，以及有新版本时是询问，还是在空闲时自动更新（仅当工作室是其仓库的克隆时；其他情况下会说明如何手动更新）。新的工作室以及每次更新都会提供它还没有的 💎 集。
- **文件夹**：你的作品存放的位置（含从 Hugging Face 下载的工作区的歌曲、回收站、画室的图片、写作室的文档），各自包含什么以及所在磁盘剩余的空间。**移动…** 可以把其中一个移到任何文件夹或磁盘：工作室先说明要做什么（同一磁盘上是重命名；另一磁盘上是复制、逐个文件核对，再切换链接），并且只在第二次确认后、没有任何渲染时才移动；旧副本改名后保留，直到你删除它。**移回原处** 把文件夹移回工作室的文件夹；**重新链接** 让工作室重新指向磁盘已恢复的文件夹。模型、LoRA 和训练集位置不变。

## DAW <!-- #daw -->

**实验性。** 通往 DAW 的路线可以工作并经过检查，但还需要在其他机器和项目上做崩溃测试，以及更多工作。

### 离开工作室的两条路 <!-- #two-ways-out-of-the-studio -->

工作室用两种方式之一交出一首歌，且只有这两种：

1. **混好的音轨**，按工作室制作、精修室完成的样子：WAV、FLAC 或 MP3，中间没有 DAW。
2. **把整段录音导入你自己的 DAW**，作为该 DAW 的项目：从那时起，一切都在工作室之外进行。不会有音频或项目回来：工作室不读取 DAW 的项目（REAPER 可以把一首歌的材料给它：歌词和一段旋律）。

**导出到 DAW** 打开这个选择：在 ☰ 中，或在精修室手头录音旁边。页面会显示工作室所在机器上有哪些 DAW（REAPER、Waveform、Bitwig）及其版本。当工作室运行在另一台电脑上、而不是你的 DAW 所在的那台（家里的服务器、路上的笔记本），用 *我用这个* 标出你的 DAW。

| DAW | 工作室给它什么 | 状态 |
|---|---|---|
| **REAPER** | 它自己的项目（.RPP）：混音、分轨、MIDI 乐谱、速度和拍号、段落、歌词、配方 | 就绪，由 REAPER 本身检查 |
| **Waveform**（Tracktion），14 或更新 | DAWproject：混音和分轨、作为音符轨的乐谱、作为标记的段落、速度和拍号 | 就绪，按格式的 schema 检查 |
| **Bitwig** | DAWproject，同上 | 就绪，按格式的 schema 检查 |
| **Studio One、Cubase**（Windows、macOS） | DAWproject，同上 | 就绪 |

### REAPER：安装 <!-- #reaper-install -->

- **Linux**：从 reaper.fm 下载 *Linux x86_64* 的 tarball；解压后运行 `./install-reaper.sh`：它会装到 `/opt/REAPER`，不带别的东西。
- **Windows、macOS**：reaper.fm 的安装程序。
- REAPER 提供 60 天全功能试用，之后要求购买许可证（个人或小企业使用 60 美元）。

### 最完整的项目：先做三步 <!-- #the-fullest-project-three-steps-first -->

项目里有什么取决于录音有什么。要全部都有：

1. 做歌时用 **完整规划**：乐谱会变成 MIDI 轨，并给出速度和拍号。（直接模式的录音没有乐谱：没有 MIDI；速度来自风格中的“NN bpm”，否则保持为占位的 120。）
2. **精修室 → 分轨**：每条分轨各占一轨（两条：人声和伴奏；四条：加上鼓、贝斯和其余部分）。
3. **精修室 → 歌词检查**：Whisper 为每一行定时；歌词行会出现在时间线上，段落（[Verse]、[Chorus]…）变成区域。

三步都不是必需的：项目会取已有的内容，并说明缺了什么。

### REAPER：导出和打开 <!-- #reaper-export-and-open -->

1. 打开录音（在创作室、精修室或资料馆中），然后 **导出到 DAW → REAPER → 导出录音**；或在任何录音上右键 → **下载 → REAPER 项目**。
2. 工作室把录音打包：音频为 48 kHz 的 24 位 WAV，所以一首七分钟、带两条分轨的歌约 350 MB。浏览器保存 `TITLE.reaper.zip`。
3. 解压到任何地方，整个解压：`TITLE/TITLE.RPP` 和 `TITLE/audio/` 保持并列。
4. 在 REAPER 中打开 `TITLE.RPP`（File → Open project，或双击）。

### 里面有什么 <!-- #what-is-inside -->

| 轨道 | 是什么 |
|---|---|
| **Mix** | 工作室渲染出的歌曲；有分轨时 **静音**，让分轨发声，混音作为参照待命 |
| **Vocals**、**Instrumental**（或 Drums、Bass、Other） | 各条分轨，都从 0 开始贯穿整首歌 |
| **Score · Vocal**、**Score · Ins** | MIDI 乐谱，每个声部一轨。这是 *写出来的* 乐谱：唱出来的歌可能偏离它。在你给它一件乐器之前它不会发声（该轨的 FX：ReaSynth，或任何 VSTi） |
| **Lyrics** | 每一行歌词作为一个空的项目，行内容写在其备注中，位于 Whisper 听到它的位置 |

- **区域**：歌词的段落，从每段第一行定时的歌词到下一段。
- **速度和拍号**：来自乐谱（其 `Q:` 和 `M:`），否则来自风格中的“NN bpm”，否则以 4/4 的 120 作为占位；项目备注会说明是哪一种。
- **项目备注**（在 REAPER 的项目设置中）：标题、风格、两个种子、录音自己的名称：回到资料馆中那段录音的路径。

### REAPER：看起来不对时 <!-- #reaper-when-something-looks-wrong -->

| 你看到的 | 原因 | 怎么做 |
|---|---|---|
| 媒体离线 | 音频文件夹不在 .RPP 旁边 | 解压整个 ZIP，让 `audio/` 留在项目旁边 |
| 没有歌词，没有区域 | 录音从未定时 | 精修室 → 歌词检查，然后重新导出 |
| 没有 MIDI 轨 | 直接模式的录音，或没有乐谱的录音 | 用完整规划制作，或在创作室中带入你自己的乐谱 |
| 速度显示 120 | 录音没有自己的速度 | 在 REAPER 中设置，或下次在风格中写“NN bpm” |
| MIDI 比人声快或慢 | 乐谱是规划，演唱是它的演绎 | 把 MIDI 当草稿用，或把它拉伸对齐分轨 |
| 希伯来语或希腊语歌词显示为方框 | REAPER 的字体缺少该文字 | 在 REAPER 的主题或首选项中换一种含这些文字的字体 |

### REAPER：从 REAPER 内部做歌 <!-- #reaper-songs-from-inside-reaper -->

`extras/reaper/` 中的三个 REAPER 动作（ReaScript，Lua）通过 API 连接工作室，可以在工作室所在的机器上，也可以在你网络中的另一台机器上。声音只走一个方向：歌曲从工作室出来进入 REAPER，没有音频或项目会回去。REAPER 给工作室的是一首歌的材料：它的歌词和旋律。

- **Ruach - Generate here**：询问风格、时长和模式；歌在工作室中制作，落在时间选区开头的一条新轨上（时长为选区的时长）。歌词来自所选项目的备注（导出的项目在那里保存每个段落的歌词），或来自对话框。**所选的 MIDI 项目就是这首歌的旋律**：其音符成为乐谱（唱最上面那一轨；和弦轨不作为旋律线给出，因为曲调可能由乐器承担），采用项目的速度和拍号，调取录音的 key snap 或音符所暗示的调，以 *仅旋律* 模式制作；新项目的备注会说明旋律是如何读取的。工作室工作时 REAPER 仍可自由使用。
- **Ruach - Bring a take**：输入词语（标题或备注，`*` 和 `?`），需要的话选一个工作区，你选的录音会落在编辑光标处。
- **Ruach - Settings**：工作室的地址、它要求时的令牌，以及从 REAPER 来的歌曲落入的工作区。

安装：把文件夹复制到 REAPER 的 `Scripts`，然后对三个脚本分别 *Actions → New action → Load ReaScript*，并运行一次 *Settings*。它们需要 `curl`（所有 Linux、macOS 以及 Windows 10 及更新版本都有）。其余见文件夹中的 README。

### DAWproject（Bitwig、Studio One、Cubase） <!-- #dawproject-bitwig-studio-one-cubase -->

右键录音 → **下载 → DAWproject**，或在 DAW 窗口的 Waveform 或 Bitwig 卡片上 *导出录音*：一个 `.dawproject` 文件，含混音和每条分轨（有分轨时混音静音）、作为音符轨的乐谱（每个声部一轨）、录音定时后作为标记的段落，采用录音的速度和拍号；风格和歌词放在它的备注中。用 DAW 的 DAWproject 导入功能打开：Waveform 14 或更新（*File > Import Other > Import a DAWproject file*；工作室要求至少 Waveform 14）、Bitwig、Studio One、Cubase。已按格式自己的 schema（Project.xsd）检查。

### 从你自己的脚本 <!-- #from-your-own-scripts -->

以上一切也是工作室的 API：`POST /api/v1/takes/NAME/reaper` 打包项目并说明从哪里获取。见 **docs/API.md**：歌曲、任务、录音、标记、工作区，以及供智能体使用的 MCP 服务器。

## 乐谱 <!-- #score -->

在完整规划中，音乐部分会在任何音发声之前写出乐谱，歌曲逐小节跟随它；用 *提供你自己的乐谱* 时，乐谱就是你的。这个标签页逐行解读它：YuE2 和 SheetSage2 所写的方言、它的两个声部如何分享小节，以及如何修改而不弄坏歌曲。

### 乐谱做什么 <!-- #what-the-score-does -->

乐谱是 ABC 文本：一个头部，然后是一到四小节一组的歌曲，每组为人声（**Vocal**）写一次、为乐器（**Ins**）写一次，在同一张小节网格上。引擎在音乐之前读它：人声的音符承载歌词，和弦引领和声，小节给出时间。

- **录音和乐谱一样长。** 六段完整规划的录音结束时与其乐谱长度相差都在 0.5–5 秒之内。最后的歌词之后的小节仍会演奏：那就是尾巴（*结束于…* 可以剪掉，或把那些小节从乐谱中去掉）。
- **乐谱里没有的不会被唱出来。** 如果规划中的段落比歌词少，最后几段主歌会被略去，或前面某段再来一次。
- **工作室严格地读它。** 检查不认识的内容都会拒绝，并指出位置：组、声部、小节。引擎也许仍能演奏这样的乐谱，但 MIDI、标记、声部移动和朗诵都需要原生方言。

### 头部 <!-- #the-head -->

八行，总是这些，按这个顺序：

```
X:1
T:
M:4/4
L:1/16
Q:1/4=85
V: Vocal clef=treble name="Vocal Melody" snm="Vocal"
V: Ins clef=treble name="Ins Melody" snm="Inst."
K:D#m
```

- `X:1` 和空的 `T:` 保持原样：标题在表单里。
- `M:` 拍号写成分数：`4/4`、`3/4`、`6/8`、`2/4`；下面的数是 2 的幂。
- `L:` 单位：不带数字的音符就是这么长。YuE2 写 `L:1/16`，即十六分音符，下文的一切都以它计数。
- `Q:1/4=` 速度：每分钟的四分音符数，整数。
- 两行 `V:` 一字不改：引擎靠它们识别声部。
- `K:` 调：大调写名称（C、G、D、A、E、B、F#、C#、F、Bb、Eb、Ab、Db、Gb、Cb），小调加 m（Am、Em、Bm、F#m、C#m、G#m、D#m、A#m、Dm、Gm、Cm、Fm、Bbm、Ebm、Abm）。同一个调的其他写法会被拒绝：写 `Eb`，不写 `D#`。

### 组、声部和小节 <!-- #groups-voices-and-bars -->

头部之后，歌曲按组进行：

```
% verse
V: Vocal
"Gm"B2B2B2B2B2B2B2G2|"Eb"B2B2B2B2B2B2B2F2|"F"F2F2F2F2F2G2F2F2|"Gm"G4z12|
V: Ins
Z4|
```

- 一组：在段落开始处写一条段落注释（`% verse`），然后是 `V: Vocal` 和一行一到四小节，然后是 `V: Ins` 和一行 **相同小节数** 的内容。每行以 `|` 结尾；不用 `||`，不用反复。
- `Z` 是一整小节休止，`Z2`、`Z3`、`Z4` 是相应的小节数；`z` 是带时值的休止，就像音符。
- 新的拍号或调以 `M:` 或 `K:` 行出现在某组的 `V:` 行之后，两个声部相同：检查要求两个声部在每一刻都在同一张网格上、同一个调中。小节内的转调写作 `[K:Em]`。

### 音符及其时值 <!-- #notes-and-their-lengths -->

- 字母表示音高：`C D E F G A B` 是从中央 C（C4）起的八度，小写 `c d e f g a b` 是高一个八度；`'` 把字母升高一个八度，`,` 降低：`B,` 是 B3，`c'` 是 C6。
- `^` 升号、`_` 降号、`=` 还原号（`^^` 和 `__` 为重升、重降）：记号对该字母一直有效到小节末尾。调号本身的升降不需要记号。
- 音符后的数字是以单位计的时值（在 `L:1/16` 下）：`1` 十六分音符，`2` 八分音符，`3` 附点八分音符，`4` 四分音符，`6` 附点四分音符，`8` 二分音符，`12` 附点二分音符，`16` 全音符；更长的用 `24`、`32` 和 `48`。只有这些：其他时值要用两个连音线连起来的音符（五个单位写 `F4-F`）。
- `-` 把一个音符连到下一个同音高的音符，跨小节线也可以：一个延长的音，一个音节。
- **每个小节的总和正好等于它的拍号**：在 `L:1/16` 下，4/4 为十六个单位，3/4 和 6/8 为十二个。短一个单位或长一个单位的小节会被拒绝，并给出数字。

### 和弦 <!-- #chords -->

- 和弦是在它开始的那个音符前用引号写出的名称：`"Gm"B2`。它一直持续到下一个和弦。和弦只放在 **Vocal** 中（检查会拒绝 Ins 中的和弦）：它们是乐队的和声，不是歌手的音符。
- 名称是一个根音（A 到 G，可带 `#` 或 `b`）加以下之一：大三和弦（什么都不加）、`m`、`dim`、`aug`、`7`、`maj7`、`m7`、`dim7`、`m7b5`、`sus4`、`sus2`、`6`、`m6`、`7sus4`、`m(maj7)`；斜线后加低音：`C/E`。
- 休止也可以带和弦：`"Bmaj7"z16` 是该和弦的一个小节、人声不唱，就像在前奏中。
- 有和弦时乐谱按 **完整规划** 演奏；没有和弦时按 **仅旋律**（旋律规划，伴奏自由）。引擎根据乐谱本身判断是哪一种。

### 段落 <!-- #sections -->

- `% intro`、`% verse`、`% chorus`、`% bridge`、`% outro` 单独成行，放在段落开始处的组标记之前。它们会作为标记进入你的 DAW（*标记*，以及 REAPER 项目内部），也是规划与你的歌词相遇的地方。
- 给乐谱提供歌词中的段落，按原来的顺序，每段都留出容纳其歌词行的空间。规划器有时写得更少：在一段很长的说唱上，文本有 32 段，它写了 2 到 17 段。在 *生成* 之前把它们补上，或缩短歌词。

### 时间 <!-- #time -->

- 一个小节的时长 = 它的四分音符数 × 60 ÷ 速度，单位为秒（速度按四分音符计）：4/4 拍 85 BPM 为 2.82 秒，103 BPM 为 2.33 秒；3/4 拍 90 BPM 为 2 秒。
- 歌曲时长 = 小节数 × 这个值。乐谱下方的检查行会写出来：`✓ Native YuE2 score · Em · 90 BPM · 3/4 · 11 bars · 0:22 · 0 sections`。
- 一行歌词需要它的音节所占的时间：每个音节一个八分音符时，一个 4/4 小节容纳 8 个，十六分音符时容纳 16 个（说唱：Viktor 的 Buratino 主歌是 `FFFFFEEEE2zDDDDD`）。
- 想让歌早点结束，就在乐谱末尾两个声部中都去掉一些小节；要加尾奏，就在那里加小节。

### 人声的空间：Vocal <!-- #the-voice-s-space-vocal -->

- Vocal 是唱出来的部分：大约一个音符一个音节，连音线连起的音符是一个延长的音节，歌手换气处为休止。检查的表格会给出音符数、每分钟的音符数、音域，以及人声发声的时间比例。
- 音符与音节：音符多于音节时，模型会把音节拉长覆盖它们，或自己加一些；少于音节时会把词挤在一起。“作曲”中的歌词节拍按每行所需的时间计数：给这一行大约那么多音符。
- 说唱很密（在一两个音高上的十六分音符：靠节奏推动），抒情曲音符较长。在行尾留一个休止：人声在那里换气，乐器在那里回应。
- 乐谱下方的声部移动（*移动*）在人声对歌手来说太高或太低的地方，按音阶级数（三度、四度、八度）移动 Vocal；和弦和 Ins 不变。

### 乐器的空间：Ins <!-- #the-instruments-space-ins -->

- Ins 是乐器自己的旋律线：前奏的连复段、乐句之间的应答、独奏、尾奏。是一条旋律，不是和弦（和弦在 Vocal 中）：一条线，YuE2 围绕它编配乐队。
- **在人声下方 Ins 大多休止。** 官方翻唱在每个演唱组下方都保持 `Z4`，在前奏、段落之间和结尾演奏；Viktor 的完整规划录音也是如此（前奏一段琶音，主歌下方 `Z4`，转折处一个过门）。在演唱句下方繁忙的 Ins 是与人声对抗的第二旋律，原生乐谱会避免这样。
- 检查用 **Ins : Vocal** 概括它，即两者音符数之比：高于 1.5 时乐器承担大部分音符，低于 0.67 时人声承担，介于两者之间则大致相当。
- 纯音乐：Vocal 整首歌都休止（`Z`），由 Ins 承担旋律。*改成纯音乐* 把乐谱中的人声旋律移到 Ins（官方配方）并勾选 *纯音乐*。器乐乐谱适配器在满强度下又有要唱的歌词时，会得到一个没有音符的人声：有歌词时把它调低（创作室 › VAE、滑块和 LoRA）。

### 在工作室中修改 <!-- #changing-it-in-the-studio -->

- **创建 ABC 乐谱**，读一读、改一改，然后 **生成**：这是得到你想要的乐谱最可靠的方法。或者在 *提供你自己的乐谱* 中自己写。
- 乐谱下方的检查会在你输入时读取它：✓ 时给出调、速度、拍号、小节数、时长和段落，每个声部一张表，以及 **Ins : Vocal** 一行；✗ 时说明哪里出了什么错：`group 3, Ins, bar 9: duration 15/4 quarter notes != meter duration 4`。
- **调性** 移动整份乐谱（就近、向上或向下）；*移动* 只按音阶级数移动 Vocal 或只移动 Ins。
- **MIDI** 可导出给 DAW（每个声部一轨，段落作为标记），也可从 DAW 导入（每个声部一条旋律线）；**标记**：段落及其秒数，以 CSV 输出。
- *从声音写出来* 和 *为这个录音扒谱*：SheetSage2 聆听一段录音，用这种方言写出它的旋律与和弦（带和弦，或只要旋律，在 *翻唱或混音* 下选择）。
- *把歌词放到这份乐谱上…*：把你的歌词行放到乐谱的小节上；下一个标签页讲述它的由来。
- 录音的乐谱以五线谱显示、全屏、打印为 PDF：创作室 › 乐谱。

### 检查说不行时 <!-- #when-the-check-says-no -->

| 它说 | 意思是 | 怎么做 |
|---|---|---|
| `duration … != meter duration …` | 某个小节的总和不对 | 数一数单位：`L:1/16` 下 4/4 为 16 |
| `unsupported duration 5` | 时值不在 1 2 3 4 6 8 12 16 24 32 48 之内 | 用连音线连两个：`F4-F` |
| `voices have different measure counts` | 一组中 Vocal 和 Ins 的小节数不同 | 给短的那个补 `Z` 小节 |
| `Native chord symbols belong in Vocal, not Ins` | Ins 中有和弦 | 把它移到 Vocal 的同一小节 |
| `unresolved tie at end of score` | 最后一个音符的连音线没有连到任何东西 | 去掉它的 `-` |
| `tie changes pitch` | 连音线连接了两个不同音高 | 连音线只连同一个音高 |
| `Unsupported key` | 调不在列表中 | 按列表的写法写同一个调：写 `Eb`，不写 `D#` |
| `expected 1–4 measures` | 一行超过四个小节 | 把这一组拆成两组 |
| `Preserve native Vocal and Ins voice definitions` | 头部被改动了 | 恢复上面那八行 |

## 乐谱上的嗓音 <!-- #voices -->

工作室宣传片的声音是这样来的：一位旁白在一段音乐垫底上念出宣传片的台词，女声在台词之间演唱，每句台词都靠近其画面所需的时刻，全部在一段录音中完成。这个方法适用于任何在伴奏上的说白、朗读或说唱；*把歌词放到这份乐谱上…* 会替你完成中间那一步。

### 垫底与它的时钟 <!-- #the-bed-and-its-clock -->

- 先做没有歌词的音乐：用垫底的风格做录音（宣传片用的是史诗预告片，D#m，103 BPM，128 秒），直到有一段听起来对了。
- 然后对它用 *从声音写出来*：SheetSage2 写出垫底自己的乐谱，它的和弦和小节。这份乐谱就是时钟：4/4 拍 103 BPM 时一个小节 2.33 秒，一个十六分音符 0.146 秒，所以只要拍号不变，第 n 小节从 n × 2.33 秒开始。
- 在这份乐谱上用完整规划演唱，新歌会保持这个时钟：相同的小节里是相同的和弦，歌词落在乐谱安排的位置。

### 落在小节上的台词 <!-- #a-line-on-its-bars -->

- 每句台词都有该说出的时刻：它的画面。它被放到最靠近那个时刻开始的小节；如果上一句在那里还在响，就放到下一个空闲小节。
- 台词变成音符：每个音节一个八分音符，落在其小节和弦的一个音上，重读的名字高一个四分音符，逗号后（一个八分音符）和句号后（一个四分音符）换气，台词的最后一个音节用四分音符并降低。旁白只需要很少的音高：和弦的音就够了，而和弦来自垫底。
- 在台词的第一个小节，乐谱加上段落注释，歌词加上相同的标签：那边是 `% verse`，这边是 `[Verse]`。一句台词一个段落：规划与歌词一一对应，什么都不会漏掉。
- 模型重音读错的词加上 Viktor 的标记：在重读元音上加锐音符（обе́щано），名字按读音拼写（俄语中为 рУ́ах，英语中为 רוּ-אַח）。

### 一段录音里的两种嗓音 <!-- #two-voices-in-one-take -->

- 旁白和女声是同一段录音，不是混音。风格同时点明两者：`male baritone narrator, spoken word, clear English diction, female a cappella vocalise, oooh aaah, epic cinematic trailer`，以及速度 `103 bpm`。
- 歌词写出每句台词，并在其后用括号写出元音吟唱：`(Ooh, aah)`。在宣传片的录音中，女声唱的就是它。
- 乐谱在台词之间的小节里给元音吟唱写上自己的音符：在和弦的高音上一个二分音符，然后小节其余部分在其吟诵音上，比旁白的音符高两个八度。垫底自己的元音吟唱保留在结尾：尾奏保留垫底的小节，连同所有音符。
- 嗓音适配器可以给旁白一个嗓音；把它调低（音乐部分 0.45、声音部分 0.3 就够了），否则它会盖过音乐。

### 多做几段，再挑最好的 <!-- #many-takes-then-the-best -->

- 每种语言六个种子，完整规划，引导 1.6，时长固定为垫底的 128 秒，乐谱和歌词保持做好的样子。每段录音念台词都略有不同：有的落得更近，有的说得更清楚。
- 台词实际在哪里：精修室 › 歌词 › *给歌词行定时* 会给出 Whisper 对每句台词逐词的时间。Whisper 自己的分段太粗：一个分段常常从台词之前的元音吟唱开始。
- 把每句台词的时间与它的小节对照：在宣传片最好的那段录音中，11 句中有 7 句在离其小节 1.5 秒以内开始（平均 1.7 秒，最远 7.5 秒）；其他录音偏得更多。乐谱引导嗓音，但不把它钉死。
- 给它们排序：先看 1.5 秒以内的台词数，再看听得出的台词，再看平均距离；听排在前面的几段。

### 双环 <!-- #the-double-ring -->

- Viktor 的话：先把音轨做对，再让影片去配合它们，哪怕长度不同。于是画面跟随录音：画面在它的台词之前出现，字幕在台词念出时出现，片尾卡一直停留到录音的最后一秒。
- 所以台词不必精确到十分之一秒地落在小节上：影片会去配合它。没有影片时也一样：按幻灯片节奏的朗读，按节拍段落的说唱。

### 现在工作室里有的 <!-- #in-the-studio-now -->

- *把歌词放到这份乐谱上…*（创作室 › 翻唱、混音和你自己的乐谱）为表单中的任何乐谱完成“台词落在小节上”这一步：你的段落、和弦音上每个音节一个八分音符、换气、前奏和尾奏，勾选时还有元音吟唱。
- *给歌词行定时*（精修室 › 歌词）给出每句台词的时间；*结束于…* 在最后一句之后结束一段录音。
- 工作室里还没有的：把每句台词放在你选定的那一秒（宣传片的画面时刻），以及按距离给录音排序。宣传片是用自己的脚本完成这些的。

| **F5**、**Ctrl+R**、**Ctrl+Shift+R** | 资料馆以外的任何地方 | 输入过内容后（自页面载入或自 **Ctrl+S** 起）会先询问，否则立即重新加载；询问时会说明重新加载会丢失什么、保留什么；表单中有歌曲时，*保存到写作室，然后重新加载* 也会把它保存在那里；**Ctrl+F5** 立即重新加载（在资料馆中 **F5** 重新读取资料库） |
| **Enter** / **Esc** | 对话框、就地重命名、LoRA 的输入值 | 确定 / 取消；在长文本对话框中 **Shift+Enter** 换行 |
| **Enter** | *从一个想法开始* | 聊天模型起草歌曲；**Shift+Enter** 换行 |
| **Ctrl+S**、**Ctrl+Shift+S** | 所有地方 | 立即保存一切：表单中的歌曲、写作室打开的文档、设置（绝不会变成浏览器的“保存网页”） |
| **Ctrl+N** | 所有地方，在 Pinokio 的窗口中 | 在创作室新建歌曲（表单中有歌词时先询问）；浏览器会把 Ctrl+N 留给自己的新窗口 |
| **Alt+K** · **Alt+J** | 歌词，创作室和写作室的 | 标记或取消标记光标所在行 · 跳到下一个标记（**Alt+Shift+J** 上一个，**Alt+Shift+K** 全部清除） |
| **Alt+E** | 创作室 | 把歌词抬到最上层，再放回；在其上按 **Shift+Tab** 会把它放进分离的表单 |
| **Alt+O** · **Alt+L** · **Ctrl+Y** · **Alt+↑ ↓** | 歌词，与 mcedit 相同 | 清除标记 · 按行号跳转 · 删除该行 · 移动该行（或选中的行） |
| **Ctrl+F** · **F4**、**Ctrl+H** | 歌词、风格、写作室的文本框 | 只在该框内查找 · 查找并替换（**Enter** 替换当前匹配，**Ctrl+Enter** 全部；**Alt+C** 区分大小写） |
| **↑ ↓** · **→** · **←** | 菜单 | 移动 · 打开子菜单 · 退出子菜单 |
| **方向键** | 主题选择器 | 在主题之间移动 |
| **+** **−** **0** | 全屏的五线谱或频谱 | 放大、缩小、恢复适应窗口；**Ctrl+滚轮** 在指针处缩放 |

| **Enter** 或 **Space** | LoRA 训练室中一次训练的卡片 | 打开该训练 |

### 鼠标 <!-- #the-mouse -->

- 在任何地方**右键单击**录音（录音列表、卡片、已固定的录音）打开它的菜单；右键单击工作区可设置锁定、重命名和删除。
- **双击**：录音列表中的录音会播放；工作区的名称可重命名；栏的边缘恢复其原有宽度；五线谱或频谱全屏打开；LoRA 的数值可以精确输入。
- **在资料馆中，像在文件管理器里一样**：勾选了一张卡片后，单击另一张卡片的任何位置也会勾选它；**Shift**+单击勾选整个范围；在卡片之间的空白处拖动会画出一条带，勾选它碰到的卡片；**Ctrl**+拖动可从任何地方画出这条带，并反转它经过的卡片：未勾选的被勾选，已勾选的被取消。带碰到边缘时页面会继续滚动。
- **批量标记**：勾选了多张时，在其中任意一张（或在已勾选栏上）点 👍、👎 或 ★ 会标记全部；如果全部已有该标记，则取消它。把多张移出工作区会先询问；回收站总会询问。
- 把指针**悬停**在被截断的工作区名称上：它会在网格上方完整显示。
- 播放器的**速度**（0.5× 到 2×）保持音高：放慢以听清细节，加快以快速浏览。

### 小技巧 <!-- #small-tricks -->

- 保留**音乐种子**，更换**声音种子**：同一首歌，重新渲染。
- 评判一件乐器之前，先在**几个种子**上听听：YuE2 会在种子和歌曲允许时让它进来。
- **固定**你经常回来听的录音（每个工作区四个）；左侧的**已固定**会列出它们全部。
- 卡片上的 **⋯** 就是它的右键菜单，方便触控板使用。

## 提示 <!-- #tips -->

### 出问题时 <!-- #when-something-goes-wrong -->

| 你看到的 | 原因 | 怎么办 |
|---|---|---|
| *乐谱成了巴别塔* | 音乐部分为乐谱写出了乱码 | 把强度调到绿色区，音乐部分少用适配器，或用直接 |
| 歌手在循环上说话 | 器乐乐谱适配器对演唱歌曲来说太强 | 保持在 0.3–0.5 |
| *GPU0 正在训练…* | 一次训练正在工作室自己的卡上进行 | 等待、停止训练，或给训练分配另一张卡（引擎 → GPU） |
| 页面提示服务器不可用 | 工作室重启了 | 等几秒；更新后重新加载页面（F5） |
| 录音的高音听起来有金属感 | VAE 的 25 帧嗡声 | 精修室 → 去嗡声，80 % |
| 歌词偏离了文本 | 音乐部分丢了歌词 | 精修室 → 歌词检查；从出错的那一分钟 *从…重新生成* |
| 你要的乐器没有出现 | 乐器何时进入由 YuE2 决定，种子影响很大 | 同样的提示词配一个**随机音乐种子**；评判前多听几段录音 |
| 乐器在演奏，但不像真的 | YuE2 对它的了解有限 | 一个乐器 LoRA（LoRA 训练室） |

### 好习惯 <!-- #good-habits -->

- 歌曲对了就保留**音乐种子**，只换**声音种子**来重新听它的声音。
- 把有效的做法记在每段录音的**备注**里：下周你就不记得是哪个种子了。
- 给每个项目一个**工作区**，并锁定完成的项目。
- 用你想听到的东西来训练：适配器会学到这组素材的声音，连同它的缺点。
