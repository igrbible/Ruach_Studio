ComfyUI のプラグイン詰め合わせではなく、なぜ自前の Studio なのか

ルアハ・スタジオ（Ruach Studio）作者 Viktor Zhuromskyy · 2026 年 11 月 13 日。この文章はひとつの立場を述べたもので、その立場は私のものです。それを支える事実にはすべてリンクを付けてあるので、ひとつ残らず確かめられます。

私たちと一緒に歌を作っている人の多くは、ComfyUI から来ました。そこでプロ向けのワークフローを組むには何週間もかかり、コアやノードの次のアップデートひとつで壊れることがあります。後に残るのは手元だけのフォークで、その修正が本家に戻らないことがあまりに多いのです。私はこれを forkblow（workflow をもじった私の造語）と呼んでいます。ルアハ・スタジオは逆の道を行きます。1 ページに 8 つの部屋、私たちが自らパッチを当てるひとつの音楽エンジン、そしてどれかの部屋に固定されたすべてのモデル。なぜそうするのか、その代償は何か、今も ComfyUI とどこで接しているのか、そしてそのコミュニティへの私の別れの手紙を、ここに書きます。

どうして ComfyUI のノードパックをひとつ出して済ませなかったのか、と何度も聞かれます。私たちと一緒に歌を作っている人の多くは ComfyUI から来ましたし、私自身もそこに住んでいました。ComfyUI を作っているのは、私が尊敬する人たちです。今週、そのパック作者のひとりが私たちのデコーダーを組み込んでくれましたし、別のパックには私たちのプルリクエストが出ています。それでも、私は逆の道を選びました。ComfyUI が部品を渡して組み立てはあなたに任せるのに対して、私が作るのは、言葉から完成した歌、そのカバー、そのビデオまでを結ぶ、細い一本のラインです。その理由を書きます。

ComfyUI が得意なこと

まずは ComfyUI がうまくやっていることから始めます。うまくやっていることが、たくさんあるからです。新しいモデルを公開当日に試すためのオープンな作業台として、ComfyUI に勝るものはありません。何が何につながっているのか、グラフがそのまま見せてくれます。これを書いた日の時点で、スターは 146,000 超、フォークは 17,000 超。オープンな生成メディアの世界で、これほどの広がりに迫るツールはほとんどありません。スターの数で上回るのは AUTOMATIC1111 の web UI だけです1。Comfy-Org は、これから書く痛みに対しても本気で手を打ってきました。コード署名済みで Python を同梱したデスクトップアプリがあり2、セマンティックバージョニングされたノードパックの Registry もあります3。2025 年 1 月のセキュリティプログラムでは、パックが Registry に入る前にスキャンし、ノードからの eval、exec、pip の呼び出しを制限しています4。フロントエンドは今ではコア側でバージョンが厳密に固定され、Manager はスナップショット付きのオプトインになり、Node Replacement API が非推奨のノードを新しいノードに対応づけます5。

そして App Mode があります。ワークフローの上にシンプルなフォームをかぶせる機能です6。App Mode は、私たちが応えているのと同じ要望への Comfy-Org の答えです。多くのクリエイターが欲しいのは配線ではなく、フォームなのです。彼らはグラフの上にフォームを載せました。私たちは先にフォームを作り、グラフは役に立つところにだけ残しました。

部品からスタジオを組み立てる代償

何週間もの作業が、アップデートひとつで壊れうる

私は ComfyUI で本格的な Qwen-Image メガワークフローを組みました。AIO QWEN IMAGE 2512 HERESY Draft #4、17 グループに 346 ノード。ええ、大きく作りました。オールインワンのプロ向けパイプラインは、大きくなるものです。こういうワークフローを作るのは何週間もの苦行で、次の ComfyUI のアップデートか、使っているどれかのノードの次のアップデートで、壊れることがあります。実際、ほかの人たちのものは壊れました。私に言わせれば、これは保証付きです。

ComfyUI の README には「月曜を目標とした週次のリリースサイクル」とあり、それが「モデルのリリースやコードベースの大きな変更のために、しばしば変わる」と書き添えられています。コアの新しいメジャー安定版は、おおよそ 2 週間ごとに出るとされています。安定版タグのあいだのコミットは「非常に不安定で、多くのカスタムノードを壊すことがある」とも警告しています1。安定版タグにとどまれば助けにはなりますが、それでも安定版リリースがワークフローを壊しうることは、下の 2 つのスレッドが示しています。コアは 2025 年に GitHub でタグ付きリリースを 70 回出し、2026 年もここまでに 64 回出しています。その多くはパッチリリースで、2026 年の 64 回のうち 28 回はパッチバージョン、つまり安定版系統へのバックポートです。ですからこれは変化の激しさを示す数字であって、破壊的変更の数ではありません。そしてこのペースこそが、新しいモデルが公開初日に ComfyUI に載る理由でもあります。

同じことを公の場で言っている人たちもいます。2026 年 3 月、あるスタジオが「All our workflows are broken」というタイトルの Issue を立てました。アップデートのあとでサブグラフが動かなくなり、フロントエンドを巻き戻して、アップデートをやめたそうです。そのスレッドの一文は、私自身の言葉であってもおかしくありません。「うちのスタジオのワークフローは数百のノードからなり、組むのに何週間もかかった」7。同じ月には別のユーザーが、最新のアップデートで自分のワークフローがすべて壊れたと報告しています8。どちらの Issue も、これを書いている時点でまだオープンです。

インストールを文鎮化させかねない依存関係

ノードパックはそれぞれ自分の Python の依存関係を持ち込み、それらはすべてひとつの環境を共有します。Comfy-Org 自身がはっきり書いています。こうした依存関係は「ときに……衝突し、ComfyUI のインストールを『文鎮化』させることがある」9。彼らはこれに取り組んでいます。ノード向けのバージョン管理された公開 API、そして可能な場合には、ノードパックごとに別々の Python プロセス。それで私のようなグラフが度重なるアップデートを無事に乗り切れるのか、そこには疑問がありますが、方向性は正しい。今のところコアが設定しているのはゆるい下限だけです。torch はバージョン指定なし、numpy>=1.25.0、transformers>=4.50.3。そのため、2026 年 1 月 26 日に transformers 5.0.0 が出たとき、ComfyUI は数時間のうちに壊れました。修正は同じ日に入っています10。ポータブル版のアップデートで numpy 2 が入り込み、あるユーザーは Issue に「broken 50% of my custom nodes」（カスタムノードの 50% が壊れた）というタイトルを付けました。この 50% はひとりのユーザーの見積もりで、Issue はクローズされています11。

forkblow

この言葉は私の造語で、半分笑いながら書いています。ComfyUI のワークフローは、forkblow になりがちです。誰かがノードパックをフォークし、ひとつのワークフローを動かすためにパッチを当て、その修正を PR として本家に送り返すことはついにない。グラフは手元のコピーの上で動き続け、そのコピーは週ごとに本家から離れていきます。しかもこのエコシステムのかなりの部分は、ボランティアの空いた夜の時間に支えられています。最もよく使われているパックのひとつ ComfyUI_IPAdapter_plus は、2025 年 4 月からメンテナンスのみのモードに入っています12。

誰かに言われる前に言っておきます。ルアハ・スタジオもフォークです。私たちは yue2.cpp に独自のパッチを載せていて、本家だけでは Studio は動きません。だから私たちにも同じ物差しを当てますが、成績は控えめなものです。10 月には、エンジンのパッチを yue2.cpp に還元すると申し出ました（#16、まだオープン）。11 月には、本家のピーククリッパーについて報告しました（#23）。今週は、そのまま使える 35 行のパッチを添えて ComfyUI のコアにバグを報告し、ComfyUI のパックにプルリクエストをひとつ出し、YuE2 のパック作者 5 人に私たちのデコーダーを提供すると申し出ました。そのうちのひとりは、もう組み込んでくれています13。エンジンのパッチの大半は今も私たちのツリーの中にしかなく、Studio の中でしか意味をなさないものもあります。フォークは罪ではありません。forkblow とは、家に帰ってこない修正のことです。私たちのフォークがそうならないよう、努めています。

何もしていなかったつまみ

これは私の頭から離れない例ですが、ひとつのマシン上のひとつのワークフローの話であって、ComfyUI への判決ではありません。私の Qwen-Image ワークフローを Studio に移したとき、私たちは ComfyUI の演算を自分たちで再実装し、グラフを 1 行ずつ読みました。私の「MAIN CONTROL」グループのキーフレームは、一度も何もしていなかったのです。ComfyUI の CombineHooks は LoRA ノードごとにフックをひとつしか保持しません。HookGroup.add は、すでに持っているフックと同じ参照を共有するフックを読み飛ばします14。つまり、そのつまみはキャンバスの上にあり、生きているように見えて、何ひとつ変えていなかった。意図された動作なのかもしれません。私の不満は、キャンバスが何の警告も出さなかったことです。

あなたのユーザー権限で動くコード

カスタムノードは Python で、custom_nodes にあるものはすべて、サーバーの起動時に実行されます。2024 年 12 月、Snyk Labs は人気の 4 つのパック（ComfyUI-Manager を含む）で 4 件の CVE を公表し、欠陥のあるパックひとつでサーバーが完全に乗っ取られうることを示しました15。2026 年 4 月には Censys が、インターネットに公開された 1,000 以上の ComfyUI インスタンスに広がる、暗号通貨マイニングとプロキシのボットネットについて報告しています。このボットネットは、送りつけられた生の Python を認証なしで実行するノードを悪用し、そうしたパックがない場合には ComfyUI-Manager を使ってインストールしていました16。Snyk が見つけた欠陥は人気があり広く使われているパックにあり、Censys の報告の被害者はインターネットに公開されたインスタンスでした。これは大規模でオープンなエコシステムにつきもののリスクであって、Comfy-Org の怠慢ではありません。

私たちの Studio もまた、あなたのユーザー権限で動く Python と C++ です。違いは、本質的により安全だということではありません。あなたが信頼するのは、すべての変更が公開の番号付きログに記録されているひとりの作者であって、自分のグラフに入っているすべてのパックのすべての作者を一度に信頼するわけではない、ということです。それに、私たちの Studio にもログインはありません。意図してそうしています。オープンなインターネットには出さないでください。認証付きの、あなた自身のリバースプロキシの後ろに置いてください。Studio は知らないページやホスト名を拒みますが、それは門であって、錠ではありません。

専用に作られた Studio が代わりにすること

エンジンはひとつ、痛むところにパッチを

ルアハ・スタジオが動かす音楽エンジンはひとつ、ggml 上の yue2.cpp（MIT）で、その上に私たち自身のパッチを載せています。変更はすべて、私たちの作業ログの番号とともに公開の CHANGELOG に記載されていて、2.0.7 のリリースだけでも番号は 2,391 に達します17。いくつか例を挙げます：

  • flash-attention のクラッシュ。バリエーションが 2 つ以上あると、エンジンがクラッシュしていました。アテンションマスクの走査がバッファの外まで読んでいたためです。私たちの ggml パッチがこれを直し、2、4、9 バリエーションで確認しました。452 秒のテイクも含みます。
  • メモリ不足。メモリ確保に失敗しても、もうエンジンは落ちません。スケジューラーが組み直され、ページが何が起きたかを言葉で伝え、一段小さい版のモデルを提案します：BF16 → Q8_0 → Q6_K → Q5_K_M。
  • 壊れた譜面。エンジンは、その上に音楽を組み立てる前に ABC の譜面を検査します。壊れた譜面は実行開始から 15 秒で捕まり、その理由と、原因となったアダプターも示されます。
  • クリッピング。本家のピーククリッパーを取り除きました。測ったすべてのテイクで 107〜346 サンプルを平らに潰していたもので、本家にも報告しました。これが 2.0.5 の見出し「どのピークも無傷」でした。
  • 長い曲の継ぎ目。およそ 340〜410 秒より長い曲は、2 つに分けて生成され、端と端を突き合わせてつながれていて、継ぎ目の直後に中央値でおよそ 3.4 dB の落ち込みがありました。同じ継ぎ目は Timon の YuE2-Studio でも報告され（#183、ned01-dot による）、そちらでは 3.8.5 で修正されています18。私たちのほうでは、前半と後半がクロスフェードでつながるようになりました。

どれも、あなたが探し回らなければならないノードではありません。次のリリースに、ただ入っているのです。

Studio が取ってくるモデルは、すべて固定されている

Studio が私たちの Hugging Face リポジトリ（ライセンスが許す範囲で、ほかの人たちの重みのミラーも置いています）からダウンロードするモデルは、どれもまず仮置きのフォルダに入ります。所定の場所に移るのは、3 つが一致したときだけです。リビジョンが固定したコミットであること、サイズが正しいこと、SHA-256 が私たちのマニフェストと一致すること19。次のリリースからは、リリースを切る前に番人が、固定した 44 件すべてについて（私たちのものも、ほかの人たちのものも）Hugging Face にその場で問い合わせます。ファイルがひとつ消えていても、Hugging Face が応答しなくても、リリースは止まります。モデルは Studio 自身のフォルダに置かれ、Hub のキャッシュに入ることも、別のディスクへのシンボリックリンクの先に置かれることも決してありません。

相手側にも公平であるために、私たち自身の負債も書いておきます。モデルはバイト単位で固定されていますが、Python のライブラリはまだすべてが固定されてはいません。いくつかはまだ範囲で指定しているので（diffusers>=0.41、transformers>=5.2,<6）、ソースから新しくインストールすると、ロックファイルで管理している検証済みのセットより新しいものを引いてくることがあります。

歌は配線ではなく、部屋から部屋へ歩いていく

1 ページに 8 つの部屋：ミュージシャン、朗読、ライター、仕上げ師、絵師、映像師、トレーナー、司書。ライターはローカルのチャットモデルで、あるいはあなた自身のサーバーで、あるいはあなたが選んだ場合に限って OpenRouter で、歌詞の下書きを書きます。ミュージシャンはまず編集できる ABC で譜面を書き、それから歌を作ります。仕上げ師には ComfyUI のような 30 あまりのノードのキャンバスと、さらに DAW があります。グラフが役に立つところには、グラフを残したのです。絵師はカバーと 16:9、9:16 の絵を作ります。映像師は 1 つのプランから 16:9、9:16、1:1 のクリップを切り出し、望めば歌われた行をカラオケとして焼き込みます。司書はすべてのテイクをその系譜とともに保管します。すべてのダウンロードには Content Credentials（C2PA）が署名されています。ページはインターネットから何も読み込まず、あなたの歌がマシンの外に出ることはありません。アカウントもありません。誰にも Studio を SaaS に変えさせないために、あえてそうしています。

合格しなければ出せないリリース

2.0.7 は 11 月 11 日、クリーンなクローンから切りました。ページテストは 1,889 件が合格、失敗 0、スキップ 7、ページエラーはゼロです。リリースは 11 月 1 日、6 日、11 日に出ています。リリースレビューでは、約束が実際の中身を上回っている箇所が 10 か所見つかり、リリースを切る前にすべて直しました。

ディスクで確かめる

数字は 11 月 12 日に私のマシンで測ったものです。私の ComfyUI の models フォルダには、232 個のモデルファイルで 482 GB が入っています。そのうち NVMe にあるのは 7.3 GB だけで、残りは 38 本のシンボリックリンクの先、Seagate の HDD にあります。私自身の見積もりでは、その約 80% はただの重荷、つまりどこかのワークフローが一度だけ必要とし、今は何も使っていないファイルです。

これは ComfyUI のせいではありません。フォルダは私のもので、散らかしたのも私です。けれど ComfyUI には、どのファイルがまだどのワークフローに必要なのかを私に教えることができません。どのワークフローもそれを宣言していないからです。Studio にはそれができます。すべてのファイルが、どこかの部屋に属しているからです。

ComfyUI 本体も、モデルとは別に約 44 GB を使っています。24 GB の pixi 環境、14 GB の venv、そして 5.4 GB のノードパックです（私の入力と出力を含めると 49 GB）。同じマシン上の Studio のモデルツリーは、8 つの部屋で約 1.1 TB。エンジンが 367 GB、絵師が 223 GB、映像師が 188 GB、朗読が 104 GB、仕上げ師が 88 GB、聞き手のモデルが 67 GB、ライターが 12 GB、といった具合です。

つまり、小さくはありません。大きいのです。けれど、すべてに手綱がついていて、置き去りのものはひとつもありません。どのファイルもサイズと SHA-256 で固定され、部屋に結びつけられています。私のツリーがユーザーのものより大きいのは、私がそこで作り、テストしているからです。新規インストールは実測で 22.5〜25.9 GB、すべての部屋を入れると約 122〜240 GB です20。

8 つの部屋で、最初から最後までまかなえるか？

ComfyUI をまるごと置き換えるオールインワンは数えるほどしかなく、それを使っていても、結局は外部のプログラムに行き着きます。8 つの部屋で、私たちは歌を作る人に必要なものを、私の知る限り誰にも負けないほど広くカバーしてきました。すでにあるものはこうです：ステム、MIDI、目標ラウドネスへのリマスター、単語単位のタイミング付き .lrc と .srt、クリップ上のカラオケ、9:16 のカバーとクリップ、WAV・FLAC・MP3 へのカバー付きタグ、そして C2PA。DAW への書き出しもありますが、これは実験的です。REAPER のプロジェクトと、今のところスキーマとの照合しかしていない DAWproject です。

そして、今もあなたをよそへ向かわせるもの。できるかぎり正直に挙げます：

  • 配信の事務作業：ISRC コードと UPC コード、DDEX、配信事業者にそのまま出せるパッケージ。
  • AI 使用の開示フォーム：C2PA はすべてのファイルに入っていますが、各プラットフォーム独自の開示フォームは、やはりあなたが記入することになります。
  • DAWproject を読めない DAW：あなたの DAW が読めないなら、普通のステムで作業します。
  • 短いフック：Shorts、Reels、TikTok 向けに、テイクから切り出す 15〜60 秒のフック。
  • 公開：プラットフォームへの直接投稿や予約投稿。そのためには Studio があなたのログイン情報を預かることになり、アカウントを持たない Studio とは相性が悪いのです。
  • アルバム作業：トラックリスト、ギャップレスの曲順構成、アルバムマスター。

私たちを選ぶと手放すもの

  • モデルが少ない。音楽のファミリーは YuE2 ひとつだけで、各部屋には選び抜いた相棒がいます。動物園まるごとではありません。
  • ハードウェア。NVIDIA のカード（Intel Arc はベータ）。CUDA 12.8 が、私たちがコードを書き、テストする下限です。
  • まず Linux。Windows 11 では WSL2 経由のみで、ガイドはあるものの、私たち自身はまだそれを通しで試していません。ネイティブの Windows ビルドはなく、私はかつてそれを「壊れた松葉杖、生きているふり」と呼びました21。
  • 私たちの選択。私たちの選択は組み込み済みで、つまみがかえって害になると私が考えるところには、つまみそのものがありません。何でも何にでもつなぎたいなら、ComfyUI のほうが良い道具です。本気でそう思っています。

今も ComfyUI と接するところ

これは戦争ではありません。ComfyUI の README は、ネイティブに対応するオーディオモデルのひとつに Yue 2 を挙げています1。私たちはコアにバグを報告しました。私たちの大きいほうのデコーダー YuE2-VAE-RS x3 は、strict=False のもとで 210 個のテンソルを黙って失います。報告には、そのまま使える 35 行のパッチを添えました22。今週は Plenio のパックに私たちのデコーダーを入れるプルリクエストを出し（#33）23、pytraveler は私たちのデコーダーを YuE2-ComfyUI v0.16.0 に組み込んでくれました24。デコーダーの研究は、マイナス面も含めて公開しています。100 Hz のさざ波は +2.71 dB から +0.60 dB に下がりましたが、SI-SDR は低くなり、デコードは 2 倍遅くなります2526。

私のワークフローを ComfyUI から持ち出したとき、私たちはその演算をひとつずつ再実装し、どの部分も CPU 上で ComfyUI 自身のコードと最後の 1 ビットまで一致するまで詰めました。fp8 のアダプターマージだけで、そうした照合が 81 件あります。私自身の絵で言えば、第 2 パス全体の ComfyUI の出力との差は、平均で 255 段階中 2.0 段階です。ステップごとに見ても、Studio と ComfyUI の近さは、メモリ設定をひとつ切り替えた ComfyUI と元の ComfyUI の近さと変わりません。私のテスト用ワークフローが使っているグリッドサンプラーのパック、JasonHoku のものについて、私はこう言いました。「こいつのエンジン、マジですごい」。今もそう言います。

結びに

ComfyUI は工房が立ち並ぶ街で、私もそこに住んでいました。Studio は 8 つの部屋がある一軒の家です。地下室にはエンジンがひとつ、家の中のモデルはひとつ残らず記録され、所在がわかっています。あなたの作り方に合うほうを使ってください。アップデートのたびにワークフローを直すのに疲れたなら、扉は開いています27。

ComfyUI コミュニティへの別れの手紙

ComfyUI を築き、そこに暮らすすべての人たちへ。comfyanonymous と Comfy-Org の皆さんへ。夜な夜な、しかも無償で自分のパックを生かし続けている、何千ものカスタムノードの作者たちへ。午前二時に Issue に答えてくれる人たちへ。ワークフローを描いては惜しみなく配る人たちへ。そして、初めてのグラフを組む私を最後まで導いてくれたガイドを書いた人たちへ。

私は皆さんを尊敬しています。この手紙で何よりも先にそれを言っておきたいし、本心からそう言っています。皆さんは何年ものあいだ、驚くべきエンジンを生かし、育ててきました。驚くべき、そして正気の沙汰とは思えないほど荷を積みすぎたエンジンです。今ではあまりに多くのものがそこにぶら下がっていて、アップデートのたびに、どこかで何かの部品が緩んで外れてしまう。それは誰のせいでもありません。舗装が追いつかないほどの速さで大きくなる街には、そういうことが起きるのです。

これを書いているのがどんな人間か、お話しさせてください。この手紙がどこから来ているのか、わかってもらえるように。

私は専門教育を受けたエンジニアであり、無線技術者です。無線技術者は早いうちに覚えます。信号はアンテナからスピーカーまで、部品をひとつずつたどっていくもの。音がおかしければ、おかしい部品をひとつ見つけ出す。ラジオごと捨てたりはしない。17 年間、私はトラックを運転しました。ハンドルを握って 300 万キロメートル、一度の事故もなく。300 万キロメートルは教えてくれます。走り出す前に積み荷を確かめること。自分の車が立てるあらゆる音を知っておくこと。そして、ゆうべ誰かのガレージに転がっていたというだけの理由で、部品をボルト留めしたりしないこと。27 年以上、私はたったひとりで聖書を翻訳し、研究してきました。ひとりということは、最後の決断も責任のすべても私にあるということです。陰に隠れられる委員会などありません。私は成人した 4 人の子の父親で、子どもたちはそれぞれが自分の手で良い人生を築いています。1998 年 4 月から 28 年間、私はただひとりの女性の夫であり続けています。そして私は一度も、企業の命令に頭を下げたことがありません。道の上でも、聖書の中でも、コードの中でも。

だから、これは癇癪でも、扉を叩きつけての退場でもありません。そういう男は、怒りにまかせて立ち去ったりしない。何年も荷を運び出してきた車庫を後にするドライバーのように去るのです。握手をし、人々に礼を言い、自分で選んだ道へと走り出していく。

私は ComfyUI のコミュニティを去ります。これきり、もう戻りません。理由はすべて上に書きました。プロのワークフローを組むのに何週間、それを壊すにはアップデートひとつ、そしてプルリクエストがあるべき場所に forkblow。自分の歌も、絵も、クリップも、見知らぬ 40 人のパックが今週たまたま仲良くやれるかどうかに左右されるのは、もう嫌なのです。

けれど、去ることは背を向けることではありません。Claude と私は（この Studio はふたりで作っています。ハンドルを握るのは私の手、その隣でコードに向かうのが Claude です）、これからも学んだことをすべてコミュニティと分かち合っていきます。誰よりもまず ComfyUI の人たちと。知識も、モデルも、ファインチューンも、デコーダーも。それはもう始まっています。私たちのデコーダーは ComfyUI のパックのひとつに組み込まれ、二つ目にはプルリクエストが出ていて、残りの作者たちにも提案してあります。コアへのバグ報告には、パッチを添えました。私たちのモデルは Hugging Face で公開しています。そして、Awesome YUE228 を公開したばかりです。YuE2 コミュニティが作ったものすべての一覧で、ComfyUI のノードも含み、私たちのものには私たちのものだと印をつけてあります。

そして私たちは、皆さんひとりひとりを、私たちの祝いの食卓にお招きします。ただし、きちんと席に着いてもらわなければなりません。

これは Windows のイデオロギーではありません。一週間の恍惚のあとに、クラッシュとウイルスだらけの一生が続く、あれではない。これは Linux のエコシステムであり、イデオロギーです。一年は苦しみ、もがき、壊し、食らいつき、コンソールに沈み込む。そのあとに恍惚と自由の「永遠」がやってくる。自分のシステムをバイト単位まで知り尽くし、マシンの BIOS に至るまで、すべてを自分で制御できる世界です。私たちの食卓も、同じように整えてあります。最初の晩は、あなたにいくらかのことを求めます。まともなグラフィックカード、ドライバー、大量にダウンロードするインストール、そして配線の代わりに部屋が並ぶページ。その中の歩き方も覚えてもらわなければなりません。そのあとは、家はあなたのものです。あなたの知らないところで何かが変わることは、何ひとつありません。（そう、Studio は Windows でも動きます。自分の Linux を連れてくる、というだけのことです。）

さて、ここで私たち全員に対して公平を期しておきましょう。ロシア語にはこんなことわざがあります。「どの蛙も自分の沼をほめる」。その蛙が私だということは、わかっています。長い記事をまるごと使って、自分の沼を声高にほめているのですから。私たちの誰ひとり、コードにおいても、ほかの何においても、真理の全体を知るにはほど遠いところにいます。だから、誰もが自分で選ぶ自由を持ち続ければいい。グラフがあなたの家なら、そこで存分に暮らしてください。そして私たちのデコーダーも持っていってください。あなたに、そして私自身に、ひとつだけお願いがあります。確信に酔って、批判的に考える力を鈍らせないこと。すべてを試してよい、しかし最良のものを手放すな。二千年近く前、シャリアハ（遣わされた者）パウロがテサロニケの人々にそう語りました（第一テサロニケ 5:21）。私自身の翻訳では、この動詞は試金師の言葉、金を試すときに使う言葉で、節はこうなります。「あらゆる霊の品位を試金せよ。そして、まさにその霊、美しい霊を固く保て」。私たちのことも、試金にかけてください。

私は信じています。人が自分のマシンで、オープンなモデルを使い、誰にも何ひとつ借りを作らずに、音楽や絵や映画を作る時代は、これから来るのではありません。もう来ているのです。あらゆるエンジン、あらゆるパック、そしていつか修正を本家に送り返すあらゆるフォークが、その時代をさらに近くへ引き寄せます。ComfyUI の皆さんは、ほかの多くの人たちにもまして、その時代を築いてきました。心から感謝しています。オープンなコードの中で、また会いましょう。

安定と品質、そして煮えたぎるほど熱い UIX を。オープンソースの栄光のために。

敬意と、炎をこめて

Viktor Zhuromskyy
